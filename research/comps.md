# Research: comps

Research across 9 comparable DSL/rules-platform VSCode extensions yields a clear picture of what "best in class" means and a ranked pattern list for a Rainbird extension.

INDIVIDUAL FINDINGS. (1) OPA/Rego: the official extension (tsandall.opa, ~119k installs, 5 stars) pairs a thin command layer (Evaluate Package/Selection, Partial Eval, Trace, Profile, Run Tests in Workspace, Toggle Coverage with in-editor covered/uncovered line highlighting) with the Regal language server, which is the most complete rules-DSL LSP found: diagnostics/linting as you type, hover docs for builtins, go-to-def, folding, document+workspace symbols, inlay hints (argument names), formatting (multiple formatters selectable), quick-fix code actions per lint rule, completions, signature help, document highlights/links, selection ranges, and — the standout — an "Evaluate" code lens on every package/rule that shows the evaluation result inline on the same line, using a convention-based input.json/input.yaml discovered by walking up from the file to workspace root. Regal also implements the Debug Adapter Protocol: launch a debug session from a code lens, breakpoints, step through rules/functions/comprehensions, inspect input/data/virtual cache. This eval-codelens + input-convention + DAP trio is the single most Rainbird-relevant pattern (Rainbird queries a goal against a knowledge map with evidence — identical shape). (2) Camunda/BPMN/DMN: no official Camunda VSCode extension (Camunda ships desktop + Web Modeler; Play mode is a Zeebe-powered in-modeler playground for running processes). The VSCode ecosystem is built on the embeddable bpmn-js/dmn-js webview libraries: Miragon "BPMN Modeler" (~11.8k installs) offers graphical editing where "the text file stays the source of truth", Ctrl+Shift+E toggle between diagram and raw XML, bpmnlint validation, element templates, a deployment sidebar (OAuth2/Basic/no-auth) that deploys to Camunda 7/8 and starts instances with payload files, element-level diagram diff with color coding, and SVG export. Red Hat's Kogito DMN Editor (~33k installs) adds a Test Scenario (SceSim) editor — a table-based scenario test authoring UI next to the decision model. Datakurre's Operaton modeler adds token simulation (animated token flow through the diagram) — the canonical "watch your logic execute" playground. (3) Drools is the cautionary tale: drools-lsp was experimental (ANTLR4 parser, C3 completion only), the repo was archived Aug 2026 and folded into apache/incubator-kie-tools; VSCode support is fragmented across tiny community extensions. Lesson: a half-committed LSP for a rules language dies. (4) Cedar (cedar-policy.vscode-cedar, ~4.2k installs, 5 stars): compact but polished — schema-based validation on open/save, entity-type/attribute autocomplete from the schema, formatting with per-file opt-out comments, outline/breadcrumbs, JSON export of policies, auto-detection of file naming conventions. (5) Prisma (3.48M installs, 5 stars) is the DSL DX gold standard: format-on-save, context-aware completion of types/relations with automatic back-relation insertion, hover docs, go-to-def, rename (F2) of models/fields with reference updating, quick-fixes ("create model" from typo), plus a cloud sidebar: sign in to Prisma Console, create/delete/push Postgres instances, embedded Prisma Studio (data CRUD in-editor), and schema (ERD-style) visualization. Prisma also ships Copilot agent-mode tools (check/create/apply migrations, provision databases), an MCP server, and a @prisma-for-github-copilot docs participant. Performance discipline matters: they moved the schema engine to in-process WASM to kill subprocess overhead. (6) GraphQL: the Foundation LSP extension (2.79M installs but only 3 stars) shows schema-aware completion/validation/hover/go-to-def incl. embedded-in-TS/JS support and multi-project graphql-config — but its config-file-required activation is the top complaint. The companion "Inline Operation Execution" extension (282k) puts a codelens above every operation, prompts for variables, and shows results in-editor. Apollo (721k, 2.5 stars) adds cloud-connected schema intelligence: schema variant switching (dev/prod), inline field latency annotations (>1ms), status-bar diagnostics — but requires apollo.config.json + GraphOS API key (friction shows in rating). (7) Terraform (6.69M installs, 2.5 stars): bundled language server (no separate install), context-aware IntelliSense, enhanced validation using detected provider versions, reference-count code lens on top-level blocks, module/provider explorer sidebar with registry doc links, HCP Terraform sidebar (log in, browse orgs/workspaces, inspect current+past runs with plan/apply logs), palette commands for init/validate/plan, and MCP server integration for AI assist. Plan graph visualization is NOT in the official extension — filled by community tools (Terraform Graph .tfgraph webview with red/green/orange change coloring, Pluralith). (8) Salesforce Extension Pack (1.94M installs, 2.5 stars): 18 extensions — org auth, deploy/retrieve, scratch orgs, Org Browser (remote metadata tree with per-item retrieve), Apex LSP + Test sidebar, Apex Replay Debugger (debug from logs), SOQL Builder (form-based visual query webview that round-trips with the .soql text file, runs queries, exports CSV/JSON, completes fields from the connected org), and Agentforce Vibes AI. Its 2.5-star rating is driven by CPU/memory bloat, node subprocess sprawl, and CLI version-management pain — the anti-pattern to avoid. (9) Neo4j: official "Neo4j for VS Code" (44k installs, 5 stars) does connection management (multiple instances incl. Aura), parameter management, Ctrl+Enter query execution with results panels, and — most interesting — database-aware language features: linting/completions tailored to the connected database version and actual labels/properties (semantic errors like unknown labels). Community "Neo4j Viz" proves in-VSCode webview graph visualization of query results/model is viable.

CROSS-CUTTING: walkthroughs (official VS Code contribution: Welcome-page multi-step checklist with theme-aware SVG media and action buttons) are the sanctioned onboarding pattern; webview custom editors over a text source of truth (all BPMN/DMN editors) with an escape hatch to raw text; test explorers/sidebars (Apex Testing, OPA workspace tests, SceSim); code lens as the universal "run this" affordance (Regal eval, GraphQL execution, Terraform reference counts); notebook-style playgrounds (MongoDB Playgrounds — executable script files with completion, 3.16M installs, 4.5 stars); Copilot chat participants with slash commands (@mongodb /query /schema /docs generates queries from natural language against the connected cluster) and MCP servers (Prisma, Terraform) as the 2025-era AI pattern.

RANKED TOP ~15 PATTERNS TO COPY (for Rainbird): 1) Full LSP with diagnostics-as-you-type, completion, hover, go-to-def, rename, outline (Prisma/Regal grade — the baseline that separates 5-star from 3-star). 2) "Evaluate/Query" code lens on every rule/goal with inline results + convention-based input/evidence file (Regal). 3) Debug Adapter Protocol stepping through rule firing with input/data inspection (Regal DAP) — maps directly to Rainbird evidence trees. 4) Webview graph visualization of the knowledge map (Neo4j Viz, Prisma ERD) — text stays source of truth, toggle to raw source (bpmn-js pattern, Ctrl+Shift+E). 5) Scenario/test editor + Test Explorer integration (DMN SceSim + Apex Test sidebar + OPA workspace tests). 6) Coverage toggle painting covered/uncovered rules in-editor (OPA). 7) Cloud sidebar: sign in, browse/pull/push knowledge maps, deploy, view remote runs/logs (Salesforce Org Browser + HCP Terraform runs view + Prisma Console). 8) Connected-service-aware intelligence: lint/complete against the live platform's concepts/instances and version (Neo4j, Apollo variants, SOQL org completion). 9) Playground/simulation mode: animated inference walkthrough (token simulation / Camunda Play analog). 10) Copilot chat participant + slash commands + MCP server (@mongodb, Prisma agent tools). 11) Visual builder webview that round-trips with text (SOQL Builder). 12) Bundled/auto-managed language server binary — zero-install activation, no config file required (Terraform bundles LS; GraphQL's config requirement = 3 stars). 13) Quick-fix code actions + rename refactoring (Prisma create-model quick fix, Regal lint fixes). 14) Walkthrough onboarding + snippets + status-bar connection state. 15) Performance discipline: in-process WASM/single LS process, no subprocess farms (Prisma WASM vs Salesforce 214% CPU complaints). Bonus anti-patterns: mandatory config files before any feature works (GraphQL/Apollo), fragmenting into 18 extensions, half-maintained LSPs (Drools).

## Key facts

- [confirmed] Official OPA extension (tsandall.opa) has ~119,088 installs, 5 stars; provides Evaluate Package/Selection, Partial Evaluation, Trace, Profile, Run Tests in Workspace, and Toggle Coverage commands, with input.json auto-discovery in file dir or workspace root — https://marketplace.visualstudio.com/items?itemName=tsandall.opa
- [confirmed] Regal language server provides diagnostics, hover, go-to-def, folding, document/workspace symbols, inlay hints (argument names), formatting (opa fmt / rego-v1 / regal fix), per-rule quick-fix code actions, completions, signature help, document highlights/links, selection ranges, and an 'Evaluate' code lens that displays evaluation results inline on the same line as the rule; inline result display is only supported in VS Code and Neovim — https://www.openpolicyagent.org/projects/regal/language-server
- [confirmed] Regal implements the Debug Adapter Protocol: debug sessions launched via code lens on a rule, breakpoints, stepping through rules/functions/comprehensions, inspection of input/data documents, local variables and the Virtual Cache — https://www.openpolicyagent.org/projects/regal/debug-adapter and https://github.com/open-policy-agent/vscode-opa
- [confirmed] Prisma extension has 3,482,928 installs, 5 stars; features: syntax highlighting, linting, completion, hover docs, go-to-def, format-on-save, F2 rename of models/enums/fields, quick-fixes (typos, create model/enum), automatic back-relation formatting — https://marketplace.visualstudio.com/items?itemName=Prisma.prisma
- [confirmed] Prisma extension includes a cloud sidebar: authenticate with Prisma Console, create/delete local and remote Prisma Postgres instances, 'Push to cloud' deploy, embedded Prisma Studio for in-editor data CRUD, and graphical database schema visualization; plus Copilot agent-mode tools (create/apply migrations, provision Postgres), an MCP server, and @prisma-for-github-copilot docs chat participant — https://www.prisma.io/docs/guides/postgres/vscode
- [confirmed] Prisma rewrote its language server to run the schema engine as in-process WebAssembly to improve extension performance — https://www.prisma.io/blog/vscode-extension-prisma-rust-webassembly
- [confirmed] HashiCorp Terraform extension has 6,691,697 installs but only 2.5/5 stars (209 reviews); bundles the language server; features context-aware IntelliSense, enhanced validation based on detected Terraform/provider versions, reference-count code lens above top-level blocks, module/provider explorer with registry doc links, and MCP server integration for AI assistance — https://marketplace.visualstudio.com/items?itemName=HashiCorp.terraform
- [confirmed] Terraform extension's HCP Terraform integration lets users log in with CLI tokens, browse workspaces by organization, and view status and detailed plan/apply logs of current and past runs inside VS Code; plan graph visualization is not included and is served by community extensions (saramorillon.terraform-graph renders .tfgraph with red/green/orange change coloring; Pluralith generates diagrams from terraform plan) — https://github.com/hashicorp/vscode-terraform README + https://marketplace.visualstudio.com/items?itemName=saramorillon.terraform-graph
- [confirmed] Cedar extension (cedar-policy.vscode-cedar) has 4,195 installs, 5 stars; schema-based validation on open/save, entity type + attribute autocomplete, formatting with // @formatter:off per-file opt-out, outline/breadcrumb/go-to-def navigation, policy-to-JSON export, auto-detection of .cedar/.cedarschema file conventions; marked Preview — https://marketplace.visualstudio.com/items?itemName=cedar-policy.vscode-cedar
- [confirmed] GraphQL Foundation LSP extension has 2,792,394 installs but 3/5 stars; schema-aware completion/validation/hover/go-to-def including embedded GraphQL in JS/TS tagged templates, multi-project via graphql-config; requires a graphql-config file to activate at all (main friction) — https://marketplace.visualstudio.com/items?itemName=GraphQL.vscode-graphql
- [confirmed] GraphQL: Inline Operation Execution extension (282,215 installs) shows a codelens above every operation; clicking executes it, prompts for variable values via dialog, and displays results/errors in the editor — https://marketplace.visualstudio.com/items?itemName=GraphQL.vscode-graphql-execution
- [confirmed] Apollo GraphQL extension (721,024 installs, 2.5 stars) offers cloud-connected schema intelligence: schema variant switching between dev/prod, inline performance annotations on fields exceeding 1ms, status bar diagnostics icon; requires apollo.config.json plus GraphOS API key in .env — https://marketplace.visualstudio.com/items?itemName=apollographql.vscode-apollo
- [confirmed] Salesforce Extension Pack has 1,937,334 installs, 2.5 stars; bundles 18 extensions: org auth + deploy/retrieve via CLI, scratch org tools, Org Browser (remote metadata tree + retrieve), Apex LSP, Apex Testing sidebar, Apex Replay Debugger, SOQL visual query builder, Agentforce Vibes AI assistant, Code Analyzer; requires sfdx-project.json to activate — https://marketplace.visualstudio.com/items?itemName=salesforce.salesforcedx-vscode
- [confirmed] SOQL Builder is a form-based webview that toggles bidirectionally with the .soql text file, runs queries against the connected org, exports results to CSV/JSON, and offers field completion after refreshing SObject definitions from the org — https://developer.salesforce.com/docs/platform/sfvscode-extensions/guide/soql-builder.html
- [confirmed] Salesforce pack's top user complaints: deploy/retrieve of a single file taking minutes, node subprocess sprawl, 'Code Helper' at 214% CPU / 1.86GB RAM, and constant CLI/extension version-management churn — https://github.com/forcedotcom/salesforcedx-vscode/issues/5854 and /issues/1592 and /issues/7132
- [confirmed] No official Camunda VSCode extension exists; Camunda ships desktop/Web Modeler, whose Play mode is a Zeebe-powered in-browser playground for validating processes (decision table rule evaluations not directly viewable in Play). VSCode BPMN/DMN editing is community-built on embeddable bpmn-js/dmn-js webviews — https://docs.camunda.io/docs/components/modeler/web-modeler/play-your-process/ and https://camunda.com/platform/modeler/
- [confirmed] Miragon BPMN Modeler (11,763 installs, 5 stars) opens .bpmn/.dmn in a graphical webview while 'the text file stays the source of truth'; Ctrl+Shift+E toggles diagram vs raw XML; bpmnlint linting, element templates via convention-based config folders, deployment sidebar (OAuth2/Basic/none) that deploys to Camunda 7/8 and starts instances with payload files, element-level diagram diff with color coding, SVG export — https://marketplace.visualstudio.com/items?itemName=miragon-gmbh.vs-code-bpmn-modeler
- [confirmed] Red Hat (Kogito) DMN Editor extension has 32,868 installs and includes a Test Scenario Editor for .scesim files (table-based decision test scenarios; DMN files must live under src/); Red Hat BPMN Editor has 73,082 installs; both support keyboard shortcut discovery via Shift+/ and configurable SVG export on save — https://marketplace.visualstudio.com/items?itemName=redhat.vscode-extension-dmn-editor and https://marketplace.visualstudio.com/items?itemName=redhat.vscode-extension-bpmn-editor
- [confirmed] Datakurre's Opinionated BPMN Modeler includes token simulation (interactive visualization of process flow/tokens through the diagram), bpmnlint with .bpmnlintrc rule config, split diagram+properties panes, and transaction boundary visualization — https://marketplace.visualstudio.com/items?itemName=datakurre.vscode-operaton-bpmn-js-modeler
- [confirmed] Drools LSP (kiegroup/drools-lsp) was experimental (ANTLR4 parser + C3 completion engine, completion-only), its repo archived August 2026 and migrated into apache/incubator-kie-tools; VSCode Drools support is otherwise fragmented tiny community extensions (formatters, syntax highlighters) — https://github.com/kiegroup/drools-lsp
- [confirmed] Official Neo4j for VS Code extension (44,184 installs, 5 stars): multi-instance connection management (incl. Aura) via sidebar/status bar, query parameter management, Ctrl+Enter execution with results opening in new panels, Cypher formatting per Neo4j styleguide, and database-aware intelligence — linting auto-matched to connected Neo4j version (5.23+) catching semantic errors like unknown labels, completions of labels/properties/database names from the live DB — https://marketplace.visualstudio.com/items?itemName=neo4j-extensions.neo4j-for-vscode and https://neo4j.com/blog/developer/run-cypher-without-leaving-your-ide-with-neo4j-vscode-extension/
- [likely] In-VSCode graph visualization of Neo4j data/results is delivered by community extensions such as Neo4j Viz (bevel-software.bevel-neo4j-viz), which connects to a database and renders explorable graph webviews — https://marketplace.visualstudio.com/items?itemName=bevel-software.bevel-neo4j-viz
- [confirmed] MongoDB for VS Code (3,160,330 installs, 4.5 stars) demonstrates the playground pattern: executable .mongodb.js playground files with shell-API autocomplete and one-click execution, saved alongside app code; plus @MongoDB Copilot chat participant with /query (natural language to query against connected cluster), /docs, and /schema slash commands, and in-editor document editing saved back to the DB — https://marketplace.visualstudio.com/items?itemName=mongodb.mongodb-vscode
- [confirmed] VS Code walkthroughs are an official contribution point: multi-step onboarding checklists on the Welcome page with checkable steps, action buttons, and theme-aware SVG media; guidance says keep steps few and visuals theme-adaptive — https://code.visualstudio.com/api/ux-guidelines/walkthroughs

## Open questions
- Exact install counts trend over time (marketplace shows point-in-time only) — which of these grew fastest after adding cloud/AI features?
- Does the official Neo4j extension now render query results as an interactive node-link graph (marketplace mentions 'results visualization capabilities' but docs page 404'd and the launch blog only describes per-query result windows)?
- What Rainbird-side APIs exist (auth, knowledge map pull/push, query/evidence-tree endpoints, versioning) to power a cloud sidebar, connected-service-aware linting, and an evidence-tree debugger — the top patterns all assume a stable platform API?
- How is RBLang parsed today (existing grammar/AST library reusable in a language server, ideally compilable to WASM per Prisma's performance lesson)?
- Whether a Copilot chat participant or MCP server matters more for Rainbird's audience (business analysts vs developers), and whether VS Code is even the right host for the analyst persona vs a web modeler with a thinner VS Code companion (the Camunda split)
- Real-world usage split between the Regal inline-eval code lens and the DAP debugger (no public telemetry found) — which to build first?
- Licensing/embedding constraints for graph-rendering libraries suitable for a knowledge-map webview (bpmn-js is bpmn.io-licensed with watermark requirements; Neo4j NVL licensing unclear)
