# Research: api

RAINBIRD AI DEVELOPER SURFACE (researched 2026-09-01; primary sources: api.rainbird.ai/docs/openapi.yaml v1.2.0, docs.rainbird.ai GitBook markdown, GitLab rainbird-ai group, npm registry).

RUNTIME/QUERY API. One small REST API ("Decisions/Evidence/Platform" in the OpenAPI spec). Servers: https://api.rainbird.ai (Community) and https://enterprise-api.rainbird.ai (Enterprise); also sa-enterprise-api.rainbird.ai (South America) and {client}-api.rainbird.ai for private environments; self-hosted (AWS-only, or on-prem Kubernetes) gets a custom URL. Live engine version (GET /version, plain text, no auth) is 4.118.0 on both Community and Enterprise today. Session lifecycle: (1) GET /start/{kmID} with X-API-Key header -> {id: sessionID, kmVersion:{id}}; query params useDraft=bool | version=int (mutually exclusive; defaults to the live version, else draft), plus legacy-documented contextid={CONTEXT_ID} which shares facts across sessions for concepts/relationships with the scope property (Go SDK still exposes contextID on NewSession). (2) POST /{sessionID}/inject with a JSON array of fact triples {subject, relationship, object, certainty} (certainty 1-100); recommended max 250 facts/request; returns {result:"OK"}. (3) POST /{sessionID}/query with {subject?, relationship (required), object?} — subject-only, object-only, or both (boolean-style check). (4) query/response/undo all return oneOf questionResponse | resultResponse. questionResponse: {question:{subject, object, objectType, objectMetadata, dataType(string|number|truth|date), relationship, type ("First Form" = yes/no confirmation, "Second Form Subject", "Second Form Object"), plural, allowCF, allowUnknown, canAdd, prompt, knownAnswers[], concepts:[{conceptType,name,type,value,invalidResponse,fsid}]}, extraQuestions:[...] (question grouping), sid}. resultResponse: {result:[{subject, relationshipType, object, certainty (1-100), factID, relationship, subjectMetadata, objectMetadata}], sid, queryProfile+stats deprecated}. (5) POST /{sessionID}/response with {answers:[{subject, relationship, object, certainty?, answer:'yes'|'no' (required for first-form), unanswered:true (skip, only if allowUnknown)}]} — loop until result. (6) POST /{sessionID}/undo with {} rolls back the last answer array and returns the prior question; repeatable. Notably, inject/query/response/undo carry security:{} in the spec (the sessionID acts as the credential; only /start, /analysis/session, and /nl/* require X-API-Key).

EVIDENCE/AUDIT. GET /analysis/evidence/{factID}/{sessionID} (header x-evidence-key; evidence secured by default, can be link-share-unlocked in Studio Publish page) returns {factID, source (enum knowledgemap|rule|answer|injection|datasource|synthesis), fact{subject{type,value,dataType}, relationship{type}, object{...}, certainty}, time (epoch ms), rule{bindings (variable map, e.g. S/O/COUNTRY), conditions[] — either relationship conditions {subject,relationship,object,certainty,factID,factKey,impact (% contribution),salience (1-100 weight),objectType,alt} or expression conditions {expression:{functions:{<call>:{facts[],result}}, text, value}, impact, salience, wasMet}, ruleMaxCertainty}}. Fact-ID prefixes observed: WA:RF (rule-inferred), WA:KF (knowledge-map), WA:AF (answer), WA:IF (injected). Full evidence tree = recursive GETs following condition factIDs (documented pattern; JS SDK has fullEvidence()). Evidence Tree UI deep-link: [STUDIO_HOST]/evidence?id=[FACT_ID]&api=[API_HOST]&sid=[SESSION_ID] (Studio hosts: app.rainbird.ai, enterprise.rainbird.ai, sa-enterprise.rainbird.ai). GET /analysis/interactions/{sessionID}?format=json|csv (header x-interaction-key) returns event log: start, inject, query, question, answer, result, datasource events with timestamps; recording is OFF by default, enabled per KM version via "Record Interactions" in Studio; only sessions started after enabling are recorded. GET /analysis/session/{sessionID}?filter=version|facts&relationships=a,b (X-API-Key) returns KM/version metadata (id, name, versionID, versionCreated, versionStatus "Draft"/"VersionN") or all session facts split into global/local/context arrays with per-fact source.

NL BETA ENDPOINTS (Rainbird Labs, open beta, no SLA, LLM = Anthropic via AWS Bedrock, EU-processed, not used for training): POST /nl/interact (headers X-API-Key + required "Version: v1") body {sessionID, userPrompt} -> {responseType: question|result|error, query{subject,relationship,object} (LLM-extracted), questions[] (standard Question schema), results[] (Pascal-case: Subject/SubjectValue/Relationship/Object/ObjectValue/Certainty/FactID/metadata), facts{injected, invalid, unmatched}, error{code,message,suggestedChatResponse,statusCode}, metadata{querySubmittedAt, languageEngineResponseTime, llmTokens{prompt/completion/total}, endpoint, sessionID}}. One active query per session (new queries ignored until a result unlocks the session); facts immutable within a session; token limits apply; core and NL endpoints can be mixed in one session. POST /nl/explain body {language (ISO 639), sessionID, factID, instructions? (free-form style/tone/template)} -> {explanation: string, metadata}. Documented integration patterns: fully-autonomous (inject-all, questions off), semi-autonomous (route questions to human/agent/vector store), interactive chat.

AUTH & LIMITS. X-API-Key header, user-scoped key found on Account page or the KM Publish page (URL + KMID + API key in one place); legacy HTTP BasicAuth still supported but discouraged. Separate x-evidence-key and x-interaction-key. x-rainbird-engine header selects experimental/alternate engine implementations (must be sent on every request of a session); JS SDK options {engine:'v2.0'}. Errors: standard HTTP; 400 missing param, 401 invalid key, 403 key lacks access, 404 session/KM not found, 5xx server. No numeric rate limits published: only production queries are rate-limited (contractual), counted only when a result is returned; Community is free, "non-commercial only" production, fair use. Technical caps: 250 facts/inject, query depth 2,000,000, strings ≤2000 chars (no " ' \ < >), number precision 15 (±999999999999999), dates ISO-8601 or epoch ms.

MANAGEMENT/AUTHORING API: none public. The spec states Knowledge Maps must be created via Rainbird Studio. Import/export is Studio-UI-only via .rbird files (exports code+layout+README of one version; excludes other versions, automated tests, agents, stats; importing into an existing map preserves KMID). Versioning is Studio-driven: editable draft + immutable numbered versions, set-live per version, restore-to-draft; API selects versions via useDraft/version params on /start. Automated tests live in Studio, run against draft, exportable/importable as JSON. No webhooks anywhere in the docs (polling the interaction log is the documented alternative). However, Rainbird Labs ships an "Agentic Knowledge Engineering" Claude Skill (rainbird-graph-creation, pilot status, ZIP distributed via the login-gated Circle forum at forum.rainbird.ai) that "builds and uploads" knowledge graphs and runs live tests via the Reasoning Engine API, with "every graph update creates a new graph in your account" — implying a non-public graph-creation/upload API. Marketing (rainbird.ai/platform) additionally claims "Every knowledge graph published is available to your applications over the REST API and to your AI agents over MCP" / "Published as an MCP tool", plus a "RAKE (Rainbird Agentic Knowledge Engineer)" AI workbench — none of this has public developer docs yet.

SDKs. Official JS monorepo gitlab.com/rainbird-ai/sdk-js -> npm @rainbird/sdk (1.5.9, updated 2026-06-23; functions start/inject/query/response/undo/evidence/fullEvidence/interaction log + RESPONSE_TYPE_QUESTION/RESULT/UNKNOWN symbols; note it uses cf rather than certainty in inject/answer payloads), @rainbird/sdk-react (RainbirdProvider/InteractionProvider contexts, hooks, components), @rainbird/sdk-react-material (Material-UI, KitchenSink drop-in Q&A agent UI). Official Go SDK gitlab.com/rainbird-ai/sdk-go (v1.9.0, Aug 2024, MIT): Client{APIKey, EnvironmentURL} with EnvCommunity/EnvEnterprise consts (EnvEnterprise = "https://api-enterprise.rainbird.ai", which conflicts with the documented enterprise-api.rainbird.ai), NewSession(kmID, contextID, useDraft, version), ResumeSession, Session.Inject/Query/Response/Undo, Client.Evidence/Interactions/SessionFacts/KnowledgeMapVersion/Version, typed interaction events, error vars. Other GitLab repos: sdk-demo (Vite+React demo of sdk-react), rbdat (trivial gunzip-JSON pretty-printer). GitHub org is RainBirdAi (12 repos, nearly all archived: rainbird-standard-agent (old agent UI, archived 2021), rainbird-analysis-ui, chirpy-ui, reframe (triples->questions), triple-webservice, MSHack, docker-workshop, step-into-tech, owasp fork, liberal, corefoo-nlp, coding guidelines) — active development is on GitLab. Legacy npm wrappers: @rainbird/yolapi + @rainbirdai/yolapi (callback-style engine wrapper). No official Python SDK (PyPI rainbird/pyrainbird = Rain Bird irrigation, unrelated). Third-party: tom-sherman/coffeebird (DSL compiling to RBLang with a CLI, npm "coffeebird"), tom-sherman/rainbird-api-js, api-evangelist/rainbird-technologies (independent API profile with generated Postman collections for Decisions/Evidence/Platform).

DATA CONNECTORS (datasources): declared inside the KM, invoked lazily mid-inference (only when the engine needs the data, before falling back to asking a question; match->infer->ask order). RBLang: <datasource hostname path method(GET|POST) name> as a child of the string concept that is the request subject; {{%S}} = subject value; <input rel="..." subject="%VAR" object="%VAR"/> binds extra graph values (multi-hop paths supported) usable as {{%VAR}} in path/headers/body; <action map="relationship name=/Response/Path"/> maps response values to facts (XPath-style / separators, JSON path with / not .); <headers><header key value/></headers>; CDATA raw request bodies for POST/XML. Datasource-derived facts carry source:"datasource" and appear as datasource events in the interaction log with relationship+certainty.

TOOLING/SANDBOX: no official CLI or Postman workspace; docs explicitly recommend importing the OpenAPI spec (https://api.rainbird.ai/docs/openapi.yaml) into Postman. Public sandbox: HelloWorld demo KM with published API key 37582f71-b9b1-4451-b9e6-c130c7fd2412 and KMID 2fd1be28-b38d-4fa3-8b9d-b0976821912c on api.rainbird.ai (languages/speaks model). docs.rainbird.ai is GitBook: llms.txt index, every page fetchable as .md, and a ?ask=<question>&goal= natural-language query API on any page URL. Older docs at rainbird-ai.gitlab.io/rainbird-docs and rainbird.redoc.ly. Studio testing surface: Quick Query, NL test agent, automated tests, external UAT links; publishable web "agents" (shareable URL/iFrame, configurable back button, question grouping, evidence-tree link, certainty display, context identifier).

## Key facts

- [confirmed] Rainbird publishes an OpenAPI 3.1 spec (v1.2.0) at https://api.rainbird.ai/docs/openapi.yaml listing two servers: https://api.rainbird.ai (Community) and https://enterprise-api.rainbird.ai (Enterprise) — https://api.rainbird.ai/docs/openapi.yaml
- [confirmed] Session lifecycle: GET /start/{kmID} (X-API-Key; optional useDraft/version params) returns {id, kmVersion.id}; then POST /{sessionID}/inject, /{sessionID}/query, /{sessionID}/response, /{sessionID}/undo; query/response/undo each return either a questionResponse or a resultResponse — https://api.rainbird.ai/docs/openapi.yaml
- [confirmed] Query body is {subject?, relationship (required), object?} — supply subject, object, or both to ask Tom->speaks->?, ?->speaks->French, or Tom->speaks->French — https://docs.rainbird.ai/rainbird/developer-docs/api-guide/example-api-requests.md
- [confirmed] Question objects carry dataType (string|number|truth|date), type (First Form yes/no vs Second Form Subject/Object), plural, allowCF, allowUnknown, canAdd, prompt, knownAnswers, concepts[] (candidate answers), and grouped questions arrive in extraQuestions[] — https://api.rainbird.ai/docs/openapi.yaml and https://docs.rainbird.ai/rainbird/knowledge-modelling/modelling-features/relationships/question-configuration.md
- [confirmed] Answers are posted as {answers:[{subject,relationship,object,certainty?,answer:'yes'|'no' for first-form}]}; skipping uses "unanswered": true (400 error if the KM disallows skipping); undo rolls back the last answer array and re-returns the question — https://docs.rainbird.ai/rainbird/developer-docs/api-guide/skipping-an-answer-to-a-question.md and openapi.yaml
- [confirmed] Results carry certainty (1-100) and a factID per result; GET /analysis/evidence/{factID}/{sessionID} returns fact source (knowledgemap|rule|answer|injection|datasource|synthesis), rule bindings, and conditions with impact/salience/certainty/wasMet; the full evidence tree is retrieved by recursively following condition factIDs — https://api.rainbird.ai/docs/openapi.yaml and https://docs.rainbird.ai/rainbird/developer-docs/api-guide/retrieving-a-full-evidence-tree-for-use-with-a-custom-ui-or-application.md
- [confirmed] Auth = X-API-Key header (key on Account page / KM Publish page); legacy HTTP BasicAuth still supported; evidence and interaction-log endpoints need separate x-evidence-key / x-interaction-key headers unless link-sharing is toggled on in Studio — https://api.rainbird.ai/docs/openapi.yaml and https://docs.rainbird.ai/rainbird/knowledge-modelling/publishing-your-km/api-management.md
- [confirmed] inject/query/response/undo require no API key in the spec (security:{}) — the sessionID from /start is the effective credential — https://api.rainbird.ai/docs/openapi.yaml
- [confirmed] GET /analysis/interactions/{sessionID}?format=json|csv returns start/inject/query/question/answer/result/datasource events; recording is off by default and enabled per KM version ('Record Interactions') in Studio — https://api.rainbird.ai/docs/openapi.yaml and https://docs.rainbird.ai/rainbird/knowledge-modelling/publishing-your-km/setting-a-live-version.md
- [confirmed] GET /analysis/session/{sessionID}?filter=version|facts returns KM version metadata or all session facts partitioned global/local/context with per-fact source — https://api.rainbird.ai/docs/openapi.yaml
- [confirmed] Beta NL endpoints: POST /nl/interact (X-API-Key + required 'Version: v1' header; {sessionID,userPrompt} -> responseType question|result|error, extracted query, injected/invalid/unmatched facts, llmTokens metadata; one active query per session) and POST /nl/explain ({language,sessionID,factID,instructions?} -> natural-language explanation); both use Anthropic models on AWS Bedrock, EU-processed — https://api.rainbird.ai/docs/openapi.yaml and https://docs.rainbird.ai/rainbird/developer-docs/api-guide/beta-apis/interact.md
- [confirmed] Limits: max 250 injected facts per request, query depth 2,000,000, strings ≤2000 chars (no " ' \ < >), number precision 15, dates ISO-8601 or epoch-ms; no numeric API rate limit published — only production queries are rate-limited (contractually) and counted only when a result is returned — https://docs.rainbird.ai/rainbird/knowledge-modelling/technical-specifications.md and https://docs.rainbird.ai/rainbird/knowledge-modelling/stats-and-reporting.md
- [confirmed] No public management/authoring API: 'Knowledge Maps must first be created via the Rainbird Studio'; import/export is Studio-only via .rbird files; versioning (draft + numbered versions, set-live) and automated tests (JSON export/import) are Studio features; no webhooks documented — https://api.rainbird.ai/docs/openapi.yaml and https://docs.rainbird.ai/rainbird/knowledge-modelling/modelling-features/other-features/import-export-knowledge-maps.md
- [confirmed] A Rainbird Labs Claude Skill ('rainbird-graph-creation', pilot) researches, builds, uploads and live-tests knowledge graphs against the Reasoning Engine API — 'every graph update creates a new graph in your Rainbird account' — implying a non-public graph-creation API; the skill ZIP is behind the login-gated Circle forum — https://docs.rainbird.ai/rainbird/rainbird-labs/agentic-knowledge-engineering-claude-skill.md
- [likely] Marketing claims MCP support: 'Every knowledge graph published is available to your applications over the REST API and to your AI agents over MCP' / 'Published as an MCP tool', plus a RAKE (Rainbird Agentic Knowledge Engineer) workbench — but no MCP developer documentation exists on docs.rainbird.ai — https://rainbird.ai/platform/
- [confirmed] Official SDKs: npm @rainbird/sdk, @rainbird/sdk-react, @rainbird/sdk-react-material (all 1.5.9, published from gitlab.com/rainbird-ai/sdk-js, last updated 2026-06-23; base exposes start/inject/query/response/undo/evidence/fullEvidence/interaction-log and RESPONSE_TYPE_* symbols; react-material ships a 'KitchenSink' complete Q&A UI) and Go SDK gitlab.com/rainbird-ai/sdk-go v1.9.0 (MIT, Aug 2024; Client/Session types, ResumeSession, contextID support) — https://registry.npmjs.org/@rainbird%2Fsdk, https://gitlab.com/rainbird-ai/sdk-js, https://pkg.go.dev/gitlab.com/rainbird-ai/sdk-go

- [confirmed] Public sandbox exists: HelloWorld demo KM with published API key 37582f71-b9b1-4451-b9e6-c130c7fd2412 and KMID 2fd1be28-b38d-4fa3-8b9d-b0976821912c on api.rainbird.ai; docs recommend importing the OpenAPI spec into Postman (no official Postman workspace or CLI) — https://docs.rainbird.ai/rainbird/developer-docs/api-guide/example-api-requests.md
- [confirmed] Legacy docs document extra headers/params still relevant: x-rainbird-engine header selects experimental/alternate engines (must persist per session) and /start/{kmID}?contextid={CONTEXT_ID} shares facts between sessions on scope-enabled concepts/relationships — https://rainbird-ai.gitlab.io/rainbird-docs/
- [confirmed] Live engine version is 4.118.0 on both api.rainbird.ai and enterprise-api.rainbird.ai (GET /version, unauthenticated, checked 2026-09-01) — https://api.rainbird.ai/version
