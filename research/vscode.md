# Research: vscode

VS Code's 2025-2026 extension platform supports every capability needed for a rich language + platform extension (language tooling, visual editing, notebooks, testing, debugging, SaaS auth, AI/Copilot integration, onboarding UX, and publishing), with all core APIs stable/finalized and an actively evolving AI layer.

LANGUAGE TOOLING. The canonical path is LSP via `vscode-languageclient` (now v10.1.0 on npm; the official guide still shows ^7.0.0 code) with `LanguageClient`, `LanguageClientOptions`, `ServerOptions`. Semantic tokens are provided by `DocumentSemanticTokensProvider`/`DocumentRangeSemanticTokensProvider` with a `SemanticTokensLegend` (23 standard token types, 14 modifiers; custom types allowed via `semanticTokenTypes`/`semanticTokenScopes` contribution points), themed via `semanticTokenColors` with TextMate fallback. For a language embedded in XML there are two documented patterns: (1) "language services" — the language server computes virtual documents (non-target regions blanked to whitespace) and delegates; (2) "request forwarding" — the client registers virtual docs via `workspace.registerTextDocumentContentProvider` and calls `commands.executeCommand('vscode.executeCompletionItemProvider')` to reuse built-in providers (limitation: cannot surface diagnostics). Microsoft ships both as samples (`lsp-embedded-language-service`, `lsp-embedded-request-forwarding`). TextMate-level embedding uses the grammars contribution's `embeddedLanguages` scope→language map plus `meta.embedded.*` scopes so bracket matching/commenting work per-region; injection grammars (`injectTo`, `injectionSelector`) extend host grammars.

VISUAL EDITOR. Webviews (`window.createWebviewPanel`, `WebviewViewProvider` for sidebar views) communicate via `postMessage`/`onDidReceiveMessage` + `acquireVsCodeApi`, persist state with `getState`/`setState` or `retainContextWhenHidden`, and are locked down via CSP, `localResourceRoots`, `asWebviewUri`, `enableScripts`. For visually editing a text document, `CustomTextEditorProvider` (registered with `window.registerCustomEditorProvider` + `customEditors` contribution: `viewType`, `selector` globs, `priority: default|option`) is the right primitive: VS Code owns the `TextDocument`, so save/backup/undo/dirty tracking come free. The documented two-way sync pattern: webview edits → extension applies `WorkspaceEdit` via `workspace.applyEdit`; document changes (including undo/redo and side-by-side text edits) → subscribe `workspace.onDidChangeTextDocument` and re-post state to the webview, guarding against echo loops. Proof at scale: hediet/vscode-drawio keeps a Draw.io graph webview and the raw XML editor live-synchronized in both directions. Note the official Webview UI Toolkit was deprecated Jan 1 2025 (repo archived); community `vscode-elements` (Lit) is the usual replacement. Binary/non-text formats instead use `CustomEditorProvider` with `CustomDocumentEditEvent` undo/redo.

NOTEBOOKS. A custom "decision test" notebook type is squarely feasible: a `NotebookSerializer` (contributed under `notebooks` with a file selector, e.g. `*.dtest.json`) maps bytes↔`NotebookData`; a `NotebookController` executes cells producing `NotebookCellOutput`/`NotebookCellOutputItem` in any mimetype; custom `NotebookRenderer`s (iframe-isolated, `vscode-notebook-renderer` ActivationFunction) render domain mimetypes and can talk to the controller via `postKernelMessage`/`onDidReceiveKernelMessage`. Microsoft's own samples include REST-query and GitHub-issue notebooks — precedent for non-Jupyter domain notebooks.

TESTING. `tests.createTestController` → hierarchical `TestItem`s (lazy via `resolveHandler`), `createRunProfile` for Run/Debug/Coverage kinds, results via `TestRun.passed/failed/errored/skipped` with `TestMessage` (expected/actual diffs, locations). Coverage API (FileCoverage, loadDetailedCoverage) finalized in 1.88; continuous ("watch") runs via `TestRunProfile.supportsContinuousRun` + `TestRunRequest.continuous`; `TestTag` filtering and publish-only controllers (CI result ingestion) supported.

DEBUGGER. DAP is runtime-agnostic; a rules/inference-engine debugger is feasible: contribute `debuggers` + `breakpoints`, implement the adapter with `@vscode/debugadapter` (renamed from vscode-debugadapter), and register a `DebugAdapterDescriptorFactory` — inline (in-extension-host JS object), server, or executable. `DebugConfigurationProvider` supplies dynamic launch configs. Inference stepping maps onto DAP threads/stackTrace/scopes/variables/stopped events; academic work (JOT 2023) demonstrates DAP reinterpretation for DSL/model debugging, and mock-debug is the reference skeleton. Breakpoints "on rules" = line breakpoints in the rules document (plus conditional/log points).

AUTH. Custom SaaS auth: contribute `authentication` (id/label), implement `AuthenticationProvider` (getSessions/createSession/removeSession/onDidChangeSessions), register via `authentication.registerAuthenticationProvider`; consumers call `authentication.getSession`. Sessions appear in the Accounts menu; `onAuthenticationRequest` activation event. Store tokens in `ExtensionContext.secrets` (SecretStorage — encrypted via Electron safeStorage on desktop, DKE on web, not synced). OAuth web-app→editor callbacks use `window.registerUriHandler` + `onUri` + `env.asExternalUri`; since 1.101 providers can declare `authorizationServerGlobs` so MCP servers can reuse extension auth.

AI/COPILOT. Four documented integration routes: (1) Chat participants (`chatParticipants` contribution + `chat.createChatParticipant`, `ChatRequestHandler`, rich `ChatResponseStream` — markdown, buttons, file trees, progress, references; slash commands; followups; automatic routing via `disambiguation`) — @-mention experts in ask mode, running inside Copilot Chat (open-sourced MIT mid-2025 and being merged into VS Code core). (2) Language Model API (`lm.selectChatModels`, `sendRequest`; user consent; rate limits; `@vscode/prompt-tsx`). (3) Language model tools (`languageModelTools` contribution + `lm.registerTool`, `invoke`/`prepareInvocation`, `toolReferenceName` for #-references, `canBeReferencedInPrompt`) — auto-invoked in agent mode, the primary way to expose domain tools to Copilot. (4) MCP: GA since 1.102; extensions ship/discover servers via `mcpServerDefinitionProviders` contribution + `lm.registerMcpServerDefinitionProvider` (`McpStdioServerDefinition`/`McpHttpServerDefinition`), or users configure `.vscode/mcp.json`; `vscode:mcp/install?{json}` deep links; VS Code supports tools, prompts (as /mcp.* slash commands), resources, sampling, elicitation, roots, OAuth 2.1 auth, and (1.109+) MCP Apps interactive UI in chat. Newer (2025-2026): `LanguageModelChatProvider` finalized 1.104 (BYOK model contribution); chatSkills contribution, Claude Agent preview, chat session item controller (proposed), Agent Host Protocol rearchitecture.

UX PLUMBING. `walkthroughs` contribution (steps with image/markdown media, completionEvents like onCommand/onSettingChanged/onContext/onLink/onView); `viewsWelcome` (markdown + command-link buttons in empty views); `views`/`viewsContainers` + `TreeDataProvider`/`window.createTreeView` (contextValue-driven menus, view/title and view/item/context actions); `languages.registerCodeLensProvider`; `window.createStatusBarItem`; task providers (`taskDefinitions` + `tasks.registerTaskProvider`, provideTasks/resolveTask, Shell/Process/CustomExecution with pseudoterminal); deep links via `vscode://<publisher>.<extension>/path?query` handled by `window.registerUriHandler`.

PUBLISHING. `@vscode/vsce` package/publish; Azure DevOps PAT (global PATs retire Dec 1 2026; Entra ID federation now recommended); publisher verification via domain; pre-release channel via `vsce publish --pre-release` with the even-minor=stable / odd-minor=pre-release convention; platform-specific targets (win32-x64, darwin-arm64, ..., web); no SVG icons. Web extensions (vscode.dev) require a `browser` entry, run in a web worker sandbox (no Node APIs, no child processes, no importScripts; fs only via `workspace.fs`; fetch+CORS), must be bundled; LSP works in a web worker (vscode-languageserver-node ≥3.16); debuggers/terminal providers don't carry over without browser entrypoints; test with `@vscode/test-web` and sideloading on vscode.dev.

- [confirmed] Latest vscode-languageclient is v10.1.0 (the official guide's sample still pins ^7.0.0) — https://www.npmjs.com/package/vscode-languageclient
- [confirmed] Semantic tokens: DocumentSemanticTokensProvider / DocumentRangeSemanticTokensProvider with SemanticTokensLegend; 23 standard token types + 14 modifiers; themes style them via semanticTokenColors with fallback mapping to TextMate scopes; custom token types via semanticTokenTypes/semanticTokenScopes contribution points — https://code.visualstudio.com/api/language-extensions/semantic-highlight-guide
- [confirmed] Embedded-language support has two documented patterns: language-services (server builds virtual documents with non-target regions blanked to whitespace and delegates) and request-forwarding (workspace.registerTextDocumentContentProvider + commands.executeCommand('vscode.executeCompletionItemProvider')); request forwarding cannot produce diagnostics; samples lsp-embedded-language-service and lsp-embedded-request-forwarding — https://code.visualstudio.com/api/language-extensions/embedded-languages
- [confirmed] TextMate grammars contribution supports embeddedLanguages (scope→language map, enables bracket matching/commenting per region via meta.embedded.* scopes) and injection grammars (injectTo, injectionSelector) — https://code.visualstudio.com/api/language-extensions/syntax-highlight-guide
- [confirmed] Webview API: window.createWebviewPanel, WebviewViewProvider (sidebar/panel), postMessage/onDidReceiveMessage + acquireVsCodeApi, getState/setState vs retainContextWhenHidden (memory cost), CSP meta tag, localResourceRoots, asWebviewUri, enableScripts, onDidDispose — https://code.visualstudio.com/api/extension-guides/webview
- [confirmed] CustomTextEditorProvider (window.registerCustomEditorProvider + customEditors contribution: viewType, displayName, selector globs, priority default|option) gives a webview editor over a TextDocument with save/backup/undo handled by VS Code; two-way sync = webview→WorkspaceEdit via workspace.applyEdit, document→webview via onDidChangeTextDocument re-render (guarding update loops); binary editors use CustomEditorProvider with CustomDocumentEditEvent undo/redo — https://code.visualstudio.com/api/extension-guides/custom-editors

- [confirmed] Testing API: tests.createTestController; hierarchical TestItem with canResolveChildren + controller.resolveHandler for lazy discovery; createRunProfile with kinds Run/Debug/Coverage; TestRun.passed/failed/errored/skipped + TestMessage (diffs, locations); FileCoverage + loadDetailedCoverage; TestTag profile filtering; publish-only controllers via createTestRun(persist:false); TestItem has no custom-data slot (use WeakMap) — https://code.visualstudio.com/api/extension-guides/testing

- [confirmed] Debugger extensions contribute debuggers + breakpoints in package.json, optionally a DebugConfigurationProvider, and supply the adapter via DebugAdapterDescriptorFactory in three modes: executable (stdio), server (socket), or inline (JS object in extension host — works for a JS-implemented inference engine); mock-debug is the reference implementation — https://code.visualstudio.com/api/extension-guides/debugger-extension

## Open questions
- Exact finalization status (proposed vs stable) as of Sep 2026 of the chat session item controller API, custom agent/skill provider APIs, and Agent Host Protocol — these were proposed in 1.109 and matter if the extension wants to appear as a first-class agent/session provider rather than a chat participant
- Whether chat participants and lm.selectChatModels work for users on the Copilot Free tier without any paid plan, and whether they function on vscode.dev (web) — docs don't state this explicitly
- Whether an inline (in-extension-host) DAP debug adapter actually runs in a web extension despite the docs listing 'debuggers' as unsupported without browser entry points — needs an experiment or issue-tracker confirmation
- Marketplace policy specifics for extensions that include AI features (GenAI usage disclosure requirements) and any review constraints for extensions bundling MCP servers
- Whether CustomTextEditorProvider undo/redo behaves acceptably for high-frequency graph edits (WorkspaceEdit granularity = undo stack granularity) — may need edit batching/coalescing strategy; not documented, needs prototyping
- Migration deltas between vscode-languageclient 7.x (doc samples) and 10.x (current) — e.g., middleware and semantic-token support changes
- Notebook kernel execution on vscode.dev for a custom controller (web worker execution of a rules engine) — supported in principle but not explicitly documented for third-party controllers
- OpenVSX publishing requirements (for Cursor/VSCodium/code-server reach) — not covered by Microsoft docs and not researched here
