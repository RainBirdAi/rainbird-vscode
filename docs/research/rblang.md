# Research: rblang

RBLang is Rainbird AI's XML-based knowledge-representation language. Every document is an XML file with declaration `<?xml version="1.0" encoding="utf-8"?>` and root `<rbl:kb xmlns:rbl="http://rbl.io/schema/RBLang">` (namespace required; the URI is an identifier only — rbl.io serves no schema). Studio (the visual knowledge-map editor) and Co-author GENERATE RBLang; the graph UI and the code are two views of the same model, switchable via the `</>` code panel, which has snippets/auto-complete (Ctrl+Space). Pasting RBLang into a new file auto-lays-out the graph.

CORE ELEMENTS (complete tag set per Rainbird's own validation prompt: rel, relinst, concept, concinst, condition, firstForm, secondFormObject, secondFormSubject; plus datasource/action/input/headers/header, meta, and an `<import km="..." versionNumber="..."/>` element seen in the official VS Code snippets):
- `<concept name="Person" type="string"/>` — types are EXACTLY string|number|date|truth (truth=boolean). Optional `behaviour="mutually-exclusive"` (string concepts only, requires exactly 2 instances). Only string concepts may be relationship SUBJECTS; any type can be object. Names unique, <2000 chars, cannot contain " ' \ < >.
- `<rel name="works in" subject="Person" object="Department" plural="false" allowUnknown="false" askable="all" allowCF="true" canAdd="none" group="Person"/>` — name required and unique map-wide; plural default false; askable ∈ all|none|secondFormObject|secondFormSubject; allowCF default true (docs spell allowCF; coffeebird emits allowCf); allowUnknown default false (skip question); canAdd ∈ all|none|subject|object; group = comma-separated question-group names. Question wording children: `<firstForm>Does %S work in the %O department?</firstForm>`, `<secondFormObject>Which department does %S work in?</secondFormObject>`, `<secondFormSubject>Who works in the %O department?</secondFormSubject>` — %S/%O placeholders, markdown allowed.
- `<concinst name="John Smith" type="Person"/>` — string concepts only (never for number/date/truth). Optional metadata child: `<concinst name="HR" type="Department"><meta type="md">Human Resources</meta></concinst>`.
- FACTS = `<relinst type="has age" subject="John Smith" object="25" cf="100"/>` (cf default 100; date objects as YYYY-MM-DD or ms timestamp; truth objects true/false).
- RULES = `<relinst>` WITH nested `<condition>` children — a rule is a relationship instance with conditions. Rule attributes: type (required), subject/object (optional fixed instance values — rule-header subject/object must be literals, NOT custom variables; %S/%O allowed), cf (max certainty, default 100), minimumRuleCertainty (default 20, must be ≤ cf), alt (evidence text, supports {{%VAR}} and dot-traversal {{%COUNTRY.is in continent}}), name (Named Rules, v4.101.0+, ≤170 chars, non-unique, ignored on facts), behaviour="top-down"|"top-down-strict" (condition ordering; absent = default certainty-driven ordering) — confirmed in a genuine Rainbird-exported map.
- CONDITIONS, three forms: (1) relationship condition `<condition rel="lives in" subject="%S" object="%COUNTRY" weight="100" behaviour="mandatory"/>`; (2) expression test `<condition expression="%AGE is greater than or equal to 18"/>`; (3) expression assignment `<condition expression="%X * 2" value="%O"/>` — the `value` attribute is the ONLY assignment mechanism; `=` inside expressions is comparison only. Condition attributes: weight (int ≥0, default 100, relative salience; 0 = no certainty impact; total must exceed 0), behaviour ∈ mandatory|optional (default mandatory; optional unmet conditions get synthesised 0%-certainty facts), alt (evidence text). Variables: %UPPER_SNAKE (letters+digits+underscore, start with letter); %S/%O are reserved for the rule's subject/object; each custom variable should appear ≥2 times; a variable is bound by relationship conditions and consumed by expressions.

EXPRESSION LANGUAGE (inside expression="..."): comparison operators with symbol AND natural-language aliases: = / equals / is equal to; != / does not equal / is not equal to; > / gt / greater than / is greater than; >= / gte; < / lt; <= / lte. Arithmetic + - * / with LEFT-TO-RIGHT evaluation (NOT PEMDAS — parentheses required to control order; coffeebird wraps every sub-expression in parens for this reason). Logic: and/or (case-insensitive since a changelog fix), combined with parentheses. String literals in SINGLE quotes ('John Smith'); instance references in conditions of coffeebird output also appear single-quoted (subject="'Fred'"). Functions: math round(x,y≤15) ceil floor abs min max mod pow sqrt factorial tan csc cot sec (atan in coffeebird); string includes/startsWith/endsWith (case- and whitespace-sensitive; negate via "= false"), regexCount(str,'/pattern/flags') JS-flavoured regex returning match count (negative error codes -1..-7), + concatenation (auto-converts numbers/dates/truth); date today() now() (unix ms), dayOfWeek dayOfMonth dayOfYear monthOfYear year, addDays/addWeeks/addMonths/addYears, subtractDays/-Weeks/-Months/-Years, secondsBetween minutesBetween hoursBetween daysBetween weeksBetween monthsBetween yearsBetween, isBeforeDate isSameDate isAfterDate, isWithinRange(val,min,max) (numbers+dates); list functions over facts with (subject, 'relationship name', object) args where * = wildcard-all: countRelationshipInstances, sumObjects, minObjects, maxObjects, joinObjects (comma-joined string), isSubset(s1,rel1,o1,s2,rel2,o2). Relationship names inside functions appear quoted in current docs ('has score') and unquoted in older real maps (requires). Null-testing is forbidden — use countRelationshipInstances(...) is equal to 0.

DATASOURCES are nested in the subject concept: `<concept name="Vehicle" type="string"><datasource hostname="https://…" path="/api/...&key_VRM={{%S}}" method="GET" name="Uk Vehicle Data"><action map="has make=/Response/DataItems/.../Make"/><input rel="owns" subject="%PERSON" object="%S"/><headers><header key="Key" value="Value"/></headers><![CDATA[body]]></datasource></concept>`. {{%S}} = datasource subject; `<input>` binds additional variables via relationships; `<action map="relationship name=/xpath/or/jsonpath"/>` maps response values to facts sharing the datasource subject (JSON paths use / not dots); CDATA for POST bodies; GET/POST only.

FILE FORMATS/TOOLING: Studio exports a knowledge map as a `.rbird` file — VERIFIED to be gzip-compressed JSON: {format:"rbird", version:"1.1", studioData:{autosave,concepts(x/y layout),errors,warnings,version}, unicronData:{concepts,datasources,rels,rblang:[array of RBLang XML lines],imports,version}} ("Unicron" = engine name). Export includes code+layout+README, not versions/tests/agents. Ecosystem tooling: coffeebird (tom-sherman, npm) — a non-XML DSL that transpiles to RBLang with CLI `coffeebird transpile [input] -o` and parse/transpile API (supports everything except compounds and datasources); rainbird-engineer-tools VS Code extension (marketplace) with RBLang XML snippets mirroring the Studio editor's, concinst/fact/CSV-to-facts generators; Rainbird's Noesis (fine-tuned Llama-3.3-70B on HuggingFace, RainbirdAI/Noesis-1.0-8bit + benjamta/NoesisAPI) generates RBLang from documents — its prompts contain Rainbird's own "Comprehensive Guide for XML Knowledge Models" and a complete library-system example map; a Claude Skill "rainbird-graph-creation" (Rainbird Labs) builds and uploads graphs via API. Queries run against relationships supplying subject (object query), object (subject query), or both (certainty/first-form query); engine follows Match→Infer→Ask. Reasoning limits: query depth 2,000,000; 250 injected facts/request; numbers ±999999999999999, precision 15.

VERBATIM SAMPLE CORPUS collected (saved under /tmp/rblang/): docs RBLang reference examples (eligibility, list aggregation), coffeebird Jest snapshots (4 full transpiled maps incl. subject/object-specific rules, expression conditions using gt and single-quoted literals), Noesis library example (~40 elements), and three genuine Rainbird-exported .rbird maps decompressed to RBLang: permit map (top-down/top-down-strict rules), isSubset dessert map, alt-text/evidence map (equals / does not equal aliases, {{%S.has gender}} traversal). Key local files: /tmp/rblang/rblang-reference_*.md, /tmp/rblang/validate_stage_1.prompt, /tmp/rblang/topdown.json, /tmp/rblang/issubset.rbird, /tmp/rblang/alttext.rbird.

## Key facts

- [confirmed] RBLang is Rainbird's XML knowledge representation language; Studio and Co-author generate it, and it can be inspected/edited in the Studio code panel (accessed via the </> icon) — https://docs.rainbird.ai/rainbird/knowledge-modelling/modelling-features/rblang-reference.md and https://docs.rainbird.ai/rainbird/knowledge-modelling/modelling-features/building-with-co-author.md
- [confirmed] Every RBLang document starts with <?xml version="1.0" encoding="utf-8"?> and root <rbl:kb xmlns:rbl="http://rbl.io/schema/RBLang">; the xmlns:rbl namespace is required; core elements are <concept>, <rel>, <concinst>, <relinst>, <condition> — https://docs.rainbird.ai/rainbird/knowledge-modelling/modelling-features/rblang-reference/xml-structure-and-namespaces.md
- [confirmed] RBLang supports exactly four concept types: string, number, date, truth; only string concepts can be relationship subjects; concept instances (<concinst>) may only be created for string concepts — https://docs.rainbird.ai/rainbird/knowledge-modelling/modelling-features/rblang-reference/concepts-relationships-and-instances.md
- [confirmed] <rel> attributes: name (required, unique map-wide), subject (string concept), object (any concept), plural (default false), askable (all|none|secondFormObject|secondFormSubject), allowCF (default true), allowUnknown (default false), canAdd (subject|object|all|none), group (comma-separated); question wording via child elements <firstForm>, <secondFormObject>, <secondFormSubject> using %S/%O placeholders — https://docs.rainbird.ai/rainbird/knowledge-modelling/modelling-features/rblang-reference/concepts-relationships-and-instances.md
- [confirmed] Rules are <relinst> elements with nested <condition> children; rule attributes: type, subject/object (optional fixed values), cf (default 100), minimumRuleCertainty (default 20, must be <= cf), alt (evidence text), name (optional, <=170 chars, added v4.101.0 'Named Rules') — https://docs.rainbird.ai/rainbird/knowledge-modelling/modelling-features/rblang-reference/rules-and-expressions.md and https://docs.rainbird.ai/rainbird/whats-new/named-rules.md
- [confirmed] Conditions have three forms: relationship (<condition rel=... subject=... object=.../>), expression test (<condition expression=.../>), and assignment (<condition expression="%X * 2" value="%O"/>); the value attribute is the only assignment mechanism — '=' in expressions is comparison only and '%O = %X * 2' is invalid — https://docs.rainbird.ai/rainbird/knowledge-modelling/modelling-features/rblang-reference/rules-and-expressions.md
- [confirmed] Condition attributes: weight (integer, default 100, relative importance; 0 = no certainty impact; sum of weights must be > 0) and behaviour (mandatory|optional, default mandatory); optional unmet conditions get synthesised facts with 0% certainty; salience chart visualises per-condition impact — https://docs.rainbird.ai/rainbird/knowledge-modelling/modelling-features/relationships/rules and https://docs.rainbird.ai/rainbird/evidence/the-evidence-tree/the-salience-chart
- [confirmed] Rule-level condition ordering is expressed as behaviour="top-down" or behaviour="top-down-strict" on <relinst> — verified in a genuine Rainbird-exported .rbird map (permit example) and matching coffeebird's transform (topDown -> 'top-down'); current docs describe the feature only as a Studio UI property ('Default'/'Top Down'/'Top Down Strict') — Rainbird Library example map https://drive.google.com/file/d/1raPkI_BInPbhf3QKYZvDdaFqoiVh-pXk (from archived https://library.rainbird.ai/sub-menu-rules/top-down-strict-top-down/) and https://raw.githubusercontent.com/tom-sherman/coffeebird/master/src/transform/rule.js
- [confirmed] Variables begin with % (e.g. %AGE); %S and %O are reserved for the rule's subject and object; custom variables are only allowed in conditions, not in the rule header (subject="%PERSON" in a relinst header is invalid) — https://docs.rainbird.ai/rainbird/knowledge-modelling/modelling-features/building-with-co-author.md and https://docs.rainbird.ai/rainbird/knowledge-modelling/modelling-features/rblang-reference/rules-and-expressions.md
- [confirmed] Expression comparison operators support symbol and natural-language aliases: = / equals / is equal to; != / does not equal / is not equal to; > / gt / greater than; >= / gte; < / lt; <= / lte — dates are excluded from these operators (use isBeforeDate etc.) — https://docs.rainbird.ai/rainbird/knowledge-modelling/modelling-features/relationships/rules/expressions-list.md (operator alias table)
- [confirmed] Expression calculations evaluate LEFT-TO-RIGHT, not PEMDAS/BODMAS; parentheses are required to control order (coffeebird parenthesises every sub-expression for this reason, with a source comment calling it 'madness') — https://docs.rainbird.ai/rainbird/whats-new/change-log.md (v4.x fix note) and https://raw.githubusercontent.com/tom-sherman/coffeebird/master/src/transform/expression.js
- [confirmed] String literals in expressions use single quotes; string functions includes()/startsWith()/endsWith() are case- and whitespace-sensitive; regexCount(str,'/pattern/flags') uses JS-flavoured regex and returns match count with negative error codes -1..-7; missing facts must be tested with countRelationshipInstances(...) is equal to 0 (no null test exists) — https://docs.rainbird.ai/rainbird/knowledge-modelling/modelling-features/relationships/rules/expressions-list.md and https://docs.rainbird.ai/rainbird/knowledge-modelling/modelling-features/rblang-reference/rules-and-expressions.md
- [confirmed] List functions take (subject, relationship, object) arguments with * as wildcard: countRelationshipInstances, sumObjects, minObjects, maxObjects, joinObjects, isSubset(s1,rel1,o1,s2,rel2,o2); date functions include today()/now() (unix ms timestamps), add/subtract Days/Weeks/Months/Years, *Between functions, isBeforeDate/isSameDate/isAfterDate, isWithinRange — https://docs.rainbird.ai/rainbird/knowledge-modelling/modelling-features/rblang-reference/functions-reference.md
- [confirmed] Math functions: + - * /, round(x,y max 15 places), ceil, floor, abs, min, max, mod, pow, sqrt, factorial, tan, csc, cot, sec (coffeebird also validates atan); logical and/or accept upper/lower/sentence case — https://docs.rainbird.ai/rainbird/knowledge-modelling/modelling-features/relationships/rules/expressions-list.md and https://docs.rainbird.ai/rainbird/whats-new/change-log.md
- [confirmed] alt (evidence text) attributes on rules and conditions support variables wrapped in {{ }} and knowledge-map dot-traversal, e.g. {{%COUNTRY.is in continent}} or {{%S.has gender}} — https://docs.rainbird.ai/rainbird/knowledge-modelling/modelling-features/relationships/rules (evidence text section) and alt-text example map https://drive.google.com/file/d/1oMZOWbclfIY6s1W0bSyPlspVB5M5m8Vk (archived https://library.rainbird.ai/sub-menu-formatting-options/alt-text/)
- [confirmed] Concept instances can carry markdown metadata via a child element: <concinst name="HR" type="Department"><meta type="md">Human Resources</meta></concinst>; metadata and question wording both support a documented markdown subset — https://docs.rainbird.ai/rainbird/knowledge-modelling/modelling-features/rblang-reference/concepts-relationships-and-instances.md and https://docs.rainbird.ai/rainbird/knowledge-modelling/modelling-features/other-features/markdown.md
- [confirmed] Datasources are declared as children of the SUBJECT concept: <datasource hostname path method name> with children <action map="relationship name=/response/path"/>, <input rel subject object/>, <headers><header key value/></headers>, and optional CDATA request body; {{%S}} injects the datasource subject and {{%VAR}} injects input-bound values; GET and POST supported; response paths use / separators (XPath-style, JSON dot-notation unsupported) — https://docs.rainbird.ai/rainbird/knowledge-modelling/modelling-features/rblang-reference/datasources-reference.md and https://docs.rainbird.ai/rainbird/knowledge-modelling/modelling-features/datasources.md
- [confirmed] Knowledge maps are exported/imported as .rbird files; the .rbird format is gzip-compressed JSON: {format:'rbird', version:'1.1', studioData:{autosave, concepts (x/y graph layout), errors, warnings}, unicronData:{concepts, datasources, rels, rblang:[XML lines array], imports}}; export includes code + graph layout + README but not versions/tests/agents — https://docs.rainbird.ai/rainbird/knowledge-modelling/modelling-features/other-features/import-export-knowledge-maps.md plus direct decompression of Rainbird-published .rbird files (gzip verified with file/gunzip); gunzip-JSON tool at https://gitlab.com/rainbird-ai/rbdat
- [likely] An <import km="..." versionNumber="..."/> element exists in RBLang (knowledge-map imports), included in the RBLang snippets of the rainbird-engineer-tools VS Code extension and as an 'imports' array in the .rbird JSON — https://raw.githubusercontent.com/tom-sherman/rainbird-engineer-tools/master/snippets.json
- [confirmed] Coffeebird (npm 'coffeebird') is a DSL that transpiles to RBLang: 'concept Person (type: string)', 'rel Person - speaks - Language', 'Language("English")', '"England" - national language - "English" (cf: 100)', rules 'speaks (cf: 75, minimumRuleCertainty: 60) { %S - lives in - %COUNTRY; %COUNTRY - national language - %O; }'; CLI: coffeebird transpile [input] -o; supports everything in RBLang except compounds and datasources — https://github.com/tom-sherman/coffeebird (README.md and syntax.md)
- [confirmed] Coffeebird's Jest snapshots contain four complete transpiled RBLang maps showing: subject/object-specific rules (<relinst type="speaks" object="German">), quoted instance refs in conditions (object="'Germany'"), transformative conditions (<condition expression="'Irish'" value="%O"/>), and gt alias usage (yearsBetween(%TODAY, %DOB) gt 500) — https://raw.githubusercontent.com/tom-sherman/coffeebird/master/test/__snapshots__/coffeebird.spec.js.snap
- [confirmed] The rainbird-engineer-tools VS Code extension (Visual Studio Marketplace, tom-sherman.rainbird-engineer-tools) provides RBLang snippets mirroring the Studio's native RBLang editor, concinst generators, and CSV-to-facts conversion — the only third-party editor support found — https://github.com/tom-sherman/rainbird-engineer-tools and https://marketplace.visualstudio.com/items?itemName=tom-sherman.rainbird-engineer-tools
- [confirmed] The Studio RBLang code editor has built-in snippets/auto-complete opened with Ctrl+Space, offering 'local' (map names), 'snippet' (expression skeletons) and 'keyword' completions — archived https://library.rainbird.ai/sub-menu-rainbird-basics/snippets-auto-complete/ (Wayback 2023) and https://docs.rainbird.ai/rainbird/knowledge-modelling/modelling-features/relationships/rules (ctrl+space expression auto-complete)

- [confirmed] Recommended element order: concepts, then relationships, then string concept instances, then facts, then rules; every concept must be connected by at least one rel; relationship names, concept names and instance names cannot contain " ' \ < > and are limited to 2000 chars — https://docs.rainbird.ai/rainbird/knowledge-modelling/modelling-features/rblang-reference/validation-checklist-and-examples.md and https://docs.rainbird.ai/rainbird/knowledge-modelling/technical-specifications.md
- [confirmed] Certainty model: facts carry cf 0-100; rule cf is the max certainty of inferred facts; minimumRuleCertainty (default 20) is the floor below which no fact is generated; condition weights are relative and combine with underlying fact certainty to produce the inferred certainty (visualised in the Salience Chart) — https://docs.rainbird.ai/rainbird/knowledge-modelling/modelling-features/relationships/rules and https://docs.rainbird.ai/rainbird/evidence/the-evidence-tree/the-salience-chart

- [confirmed] Engine limits: query depth 2,000,000; 250 facts per injection request; numbers max ±999999999999999 with precision 15; dates as ms timestamps or ISO 8601 YYYY-MM-DD — https://docs.rainbird.ai/rainbird/knowledge-modelling/technical-specifications.md

## Open questions
- What is the syntax of RBLang 'compounds' (named by coffeebird as an RBLang feature it doesn't support)? No public documentation or sample was found — likely only visible in Studio-exported maps that use it.
- Exact serialisation of the <import km=... versionNumber=.../> element in current-generation maps (only evidence: VS Code snippet file and the empty 'imports' array in .rbird JSON) — is it still supported in the current engine?
- Whether attribute casing allowCf vs allowCF are both accepted by the parser (docs use allowCF, coffeebird emits allowCf; the engine may be case-insensitive here) — needs a live round-trip test in Studio.
- Whether the rule-header 'behaviour' attribute accepts any values beyond top-down and top-down-strict, and how the 'Default' ordering is serialised (probably by omitting the attribute).
- Full schema of the Studio/graph API used by the Claude Skill to upload RBLang programmatically (not in the public API reference, which covers only decisions/evidence/platform endpoints).
- Are relationship names inside list-function arguments required to be single-quoted? Current docs quote them ('has score') but older official maps use unquoted names (requires) — the grammar should probably accept both.
- Whether <firstForm> has subject/object variants beyond the three documented question elements (Noesis validate_stage_2 mentions a '<firstFormObjcet>' [sic] tag, suggesting an internal firstFormObject variant may exist).
- The precise certainty-combination formula (how condition weights and fact CFs produce inferred fact CF) — the salience docs describe it qualitatively; an exact formula was referenced in a retired 'Certainty Factor Calculator' library page not recovered.
