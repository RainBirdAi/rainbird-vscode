# Gap research: RBLang undocumented syntax (compounds, import, firstFormObject) and any formal schema/XSD

DECISIVE FIND: Rainbird Studio's live production JS bundle (https://app.rainbird.ai/static/js/main.70f77c79.chunk.js, fetched 2026-09-01, saved at /tmp/rbl-research/main.js) embeds Rainbird's own RBLang XML validator (webpack module 1579). This is the closest thing to an official machine-readable schema that exists, and it answers (a), (b), (c) authoritatively. An identical schema appears in the July-2024 Wayback copy (main.96adb30c.chunk.js), so it is stable.

VALIDATOR TABLE (verbatim structure, de-minified; extracted copy at /tmp/rbl-research/rblang_schema_raw.js):
- rbl:kb: exactly 1; no text; required attr xmlns:rbl which must equal "http://rbl.io/schema/RBLang"; children = compound, concept, concinst, import, rel, relinst.
- compound: required attrs subject, type, object; children: relinst (required type, object; optional cf). No text.
- concept: required name, type (enum string|date|truth|number); optional scope, behaviour (enum mutually-exclusive|mutex|mx); child: datasource.
- datasource (child of concept only, NOT of rbl:kb): text allowed (request body); required hostname (must start http:// or https://); optional path, method (GET|POST), name; children: action (required map, min 1, actions nest recursively: s.children.action=s), input (optional rel, subject, object, value, expression), headers > header (required key, value).
- concinst: required name, type; child meta (optional type; text allowed).
- import: required km, versionNumber; optional username (validator: non-empty string).
- rel: required name, subject, object; optional allowCF, allowUnknown, askable, canAdd, group, plural, scope; enums: allowCF/allowUnknown/plural ∈ true|false; askable ∈ true|false|all|none|secondFormSubject|secondFormObject (note legacy true/false accepted); canAdd ∈ all|"subject,object"|"object,subject"|subject|object|none; scope ∈ context; children: firstForm, secondFormObject, secondFormSubject (each max 1, text). No firstFormObject/firstFormSubject.
- relinst: required type; optional subject, object, cf, behaviour, minimum-rule-certainty, alt, name; child condition with optional attrs funct, expression, salience, weight, behaviour, rel, subject, object, value, alt (condition has NO required attrs). Bug in shipped code: the validators:{behaviour:["optional","mandatory"]} object is nested inside relinst's children map, so condition@behaviour values are not actually enforced and a literal <validators> child of relinst would be "recognised".
Validator emits messages worth mimicking: "<X ...> has text but is not a text element", "X element has missing attribute: Y", "X element has unrecognised attribute: Y", "X has invalid value for attribute: Y=\"Z\"", "Unrecognised element: X", "Not enough <X ...> elements (min N)", "Too many <X ...> elements (max N)".

(a) COMPOUNDS — SYNTAX FOUND (from Rainbird's validator), semantics/real-world sample NOT FOUND. Serialisation implied by the schema: <compound subject="…" type="…" object="…"> containing one or more <relinst type="…" object="…" cf="…"/>. Studio's parser selectors only process rbl:kb>{concept,rel,concinst,relinst,import} — never compound — so Studio tolerates compound in validation but does not model/serialize it (legacy engine feature). coffeebird's only mention (syntax.md line 3, verbatim): "**Note:** Coffeebird natively supports pretty much all of the syntax that is available via RBLang. The only exceptions to this is are **compounds** and **datasources**." No sample exists in coffeebird full git history, its issues, GitHub/GitLab public code (Sourcegraph 0 hits for xmlns:rbl), npm packages, Wayback (docs.rainbird.ai, feedback.rainbird.ai UserVoice KB, rainbird-ai.gitlab.io GitBook = API-only docs, support.rainbird.ai, zendesk), or the current docs' AI ask endpoint ("I cannot find information about a <compound> XML element"). Grammar recommendation: encode the validator shape above; mark semantics unknown.

(b) IMPORT — CONFIRMED, current feature. Studio's live bundle fully implements linked knowledge maps (addLKM/rmLKM/depsLKM/_sortImports). Serializer emits verbatim: `  <import km="${n}" versionNumber="${r}"/>` (self-closing, two-space indent; username never emitted, only tolerated by validator). Parser resolves rbl:kb>import elements to dependency keys `${km}@${versionNumber}`; unresolved deps produce error {message:"DEPSREQUIRED"}. In .rbird JSON, imports is an array of "km@versionNumber" strings; linked KMs are stored under "linked" with rel/concept ids namespaced as "[importId]id". The feature is absent from all current public docs (the Import/Export docs page covers only .rbird file UI import/export) — undocumented but engine/Studio-supported. The third-party VS Code snippet (github.com/tom-sherman/rainbird-engineer-tools snippets.json) matches: `<import km="$1" versionNumber="$2" />`.

(c) firstFormObject/firstFormSubject — DO NOT EXIST. The Studio validator allows only firstForm, secondFormObject, secondFormSubject (max 1 each) inside rel; current official RBlang reference (docs.rainbird.ai …/rblang-reference/concepts-relationships-and-instances.md) shows only those three. The '<firstFormObjcet>' string is a typo in the Noesis validation prompt, found verbatim in github.com/benjamta/NoesisAPI (Ben Taylor is Rainbird's founder/CTO) at rainbird/noesis/prompts/validate_stage_2.prompt and "validate full.prompt" lines 95-102: "6. The only valid tags are: <rel> <relinst> <concept> <concinst> <condition> <firstFormObjcet> <secondFormObject>". That list is sloppy (omits firstForm/secondFormSubject/meta etc.); it should not drive the grammar.

SCHEMA QUESTION — No XSD/RelaxNG/DTD/JSON-Schema for the XML exists publicly. rbl.io is domain-squatted: http://rbl.io 301→https, whose cert is CN=neronote.com and which 301s /schema/RBLang to https://www.apposta.com/schema/RBLang (a shirt shop); Wayback shows rbl.io 404 since 2018. However, the Studio bundle contains (i) the module-1579 XML validation table above, (ii) AJV JSON Schemas (modules 1572-1578, extracted verbatim in the transcript) for the .rbird JSON model: Action (array of {rel,xpath,action$ref}), Concept (type enum string|date|truth|number, mutuallyExclusive bool), ConcInst (meta array of {value,type}), Datasource (hostname pattern ^$|^http(s)?://, method GET|POST, headers, body), Fact (certainty int 0-100 default 100, object string|number|boolean), Relationship (plural default false, allowCF default true, allowUnknown default false, canAskSubject/canAskObject/canAddSubject/canAddObject defaults true, groups[], questions{firstForm,secondFormSubject,secondFormObject}), Rule (behaviour enum auto|top-down|top-down-strict default auto; minCertainty default 20 min 1 max 100; altText/name nullable; conditions oneOf required [expression] OR [rel,subject,object]; weight default 100 min 0; mandatory default true), and (iii) cheerio PARSE_OPTIONS (module 550): xmlMode true, decodeEntities false, lowerCaseTags false, recogniseSelfClosing true. Bonus: module 824 lists all 51 expression functions: abs addDays addMonths addWeeks addYears atan2 ceil cot countRelationshipInstances csc dayOfMonth dayOfWeek dayOfYear daysBetween endsWith factorial floor hoursBetween includes isAfterDate isBeforeDate isSameDate isSubset isWithinRange joinObjects max maxObjects min minObjects minutesBetween mod monthOfYear monthsBetween now pow regexCount round sec secondsBetween sqrt startsWith subtractDays subtractMonths subtractWeeks subtractYears sumObjects tan today weeksBetween year yearsBetween.
