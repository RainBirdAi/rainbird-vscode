# Research: api

RAINBIRD AI DEVELOPER SURFACE (researched 2026-09-01; primary sources: api.rainbird.ai/docs/openapi.yaml v1.2.0, docs.rainbird.ai GitBook markdown, GitLab rainbird-ai group, npm registry).

RUNTIME/QUERY API. One small REST API ("Decisions/Evidence/Platform" in the OpenAPI spec). Servers: https://api.rainbird.ai (Community) and https://enterprise-api.rainbird.ai (Enterprise); also sa-enterprise-api.rainbird.ai (South America) and {client}-api.rainbird.ai for private environments; self-hosted (AWS-only, or on-prem Kubernetes) gets a custom URL. Live engine version (GET /version, plain text, no auth) is 4.118.0 on both Community and Enterprise today. Session lifecycle: (1) GET /start/{kmID} with X-API-Key header -> {id: sessionID, kmVersion:{id}}; query params useDraft=bool | version=int (mutually exclusive; defaults to the live version, else draft), plus legacy-documented contextid={CONTEXT_ID} which shares facts across sessions for concepts/relationships with the scope property (Go SDK still exposes contextID on NewSession). (2) POST /{sessionID}/inject with a JSON array of fact triples {subject, relationship, object, certainty} (certainty 1-100); recommended max 250 facts/request; returns {result:"OK"}. (3) POST /{sessionID}/query with {subject?, relationship (required), object?} — subject-only, object-only, or both (boolean-style check). (4) query/response/undo all return oneOf questionResponse | resultResponse. questionResponse: {question:{subject, object, objectType, objectMetadata, dataType(string|number|truth|date), relationship, type ("First Form" = yes/no confirmation, "Second Form Subject", "Second Form Object"), plural, allowCF, allowUnknown, canAdd, prompt, knownAnswers[], concepts:[{conceptType,name,type,value,invalidResponse,fsid}]}, extraQuestions:[...] (question grouping), sid}. resultResponse: {result:[{subject, relationshipType, object, certainty (1-100), factID, relationship, subjectMetadata, objectMetadata}], sid, queryProfile+stats deprecated}. (5) POST /{sessionID}/response with {answers:[{subject, relationship, object, certainty?, answer:'yes'|'no' (required for first-form), unanswered:true (skip; accepted when the question has allowUnknown or non-empty knownAnswers, verified live 2026-10-07)}]} — loop until result. (6) POST /{sessionID}/undo with {} rolls back the last answer array and returns the prior question; repeatable. Notably, inject/query/response/undo carry security:{} in the spec (the sessionID acts as the credential; only /start, /analysis/session, and /nl/* require X-API-Key).

EVIDENCE/AUDIT. GET /analysis/evidence/{factID}/{sessionID} (header x-evidence-key; evidence secured by default, can be link-share-unlocked in Studio Publish page) returns {factID, source (enum knowledgemap|rule|answer|injection|datasource|synthesis; live, knowledge-map facts arrive as "km", see Verified live 2026-10-07), fact{subject{type,value,dataType}, relationship{type}, object{...}, certainty}, time (epoch ms), rule{bindings (variable map, e.g. S/O/COUNTRY), conditions[] — either relationship conditions {subject,relationship,object,certainty,factID,factKey,impact (% contribution),salience (1-100 weight),objectType,alt} or expression conditions {expression:{functions:{<call>:{facts[],result}}, text, value}, impact, salience, wasMet}, ruleMaxCertainty}}. Fact-ID prefixes observed: WA:RF (rule-inferred), WA:KF (knowledge-map), WA:AF (answer), WA:IF (injected). Full evidence tree = recursive GETs following condition factIDs (documented pattern; JS SDK has fullEvidence()). Evidence Tree UI deep-link: [STUDIO_HOST]/evidence?id=[FACT_ID]&api=[API_URL]&sid=[SESSION_ID] (the documented example passes the full API URL, e.g. https://enterprise-api.rainbird.ai; Studio hosts: app.rainbird.ai, enterprise.rainbird.ai, sa-enterprise.rainbird.ai). GET /analysis/interactions/{sessionID}?format=json|csv (header x-interaction-key) returns event log: start, inject, query, question, answer, result, datasource events with timestamps; recording is OFF by default, enabled per KM version via "Record Interactions" in Studio; only sessions started after enabling are recorded. GET /analysis/session/{sessionID}?filter=version|facts&relationships=a,b (X-API-Key) returns KM/version metadata (id, name, versionID, versionCreated, versionStatus "Draft"/"VersionN") or all session facts split into global/local/context arrays with per-fact source.

NL BETA ENDPOINTS (Rainbird Labs, open beta, no SLA, LLM = Anthropic via AWS Bedrock, EU-processed, not used for training): POST /nl/interact (headers X-API-Key + required "Version: v1") body {sessionID, userPrompt} -> {responseType: question|result|error, query{subject,relationship,object} (LLM-extracted), questions[] (standard Question schema), results[] (Pascal-case: Subject/SubjectValue/Relationship/Object/ObjectValue/Certainty/FactID/metadata), facts{injected, invalid, unmatched}, error{code,message,suggestedChatResponse,statusCode}, metadata{querySubmittedAt, languageEngineResponseTime, llmTokens{prompt/completion/total}, endpoint, sessionID}}. One active query per session (new queries ignored until a result unlocks the session); facts immutable within a session; token limits apply; core and NL endpoints can be mixed in one session. POST /nl/explain body {language (ISO 639), sessionID, factID, instructions? (free-form style/tone/template)} -> {explanation: string, metadata}. Documented integration patterns: fully-autonomous (inject-all, questions off), semi-autonomous (route questions to human/agent/vector store), interactive chat.

AUTH & LIMITS. X-API-Key header, user-scoped key found on Account page or the KM Publish page (URL + KMID + API key in one place); legacy HTTP BasicAuth still supported but discouraged. Separate x-evidence-key and x-interaction-key. x-rainbird-engine header selects experimental/alternate engine implementations (must be sent on every request of a session); JS SDK options {engine:'v2.0'}. Errors: standard HTTP; 400 missing param, 401 invalid key, 403 key lacks access, 404 session/KM not found, 5xx server. No numeric rate limits published: only production queries are rate-limited (contractual), counted only when a result is returned; Community is free, "non-commercial only" production, fair use. Technical caps: 250 facts/inject, query depth 2,000,000, strings ≤2000 chars (no " ' \ < >), number precision 15 (±999999999999999), dates ISO-8601 or epoch ms.

MANAGEMENT/AUTHORING API: none public. The spec states Knowledge Maps must be created via Rainbird Studio. Import/export is Studio-UI-only via .rbird files (exports code+layout+README of one version; excludes other versions, automated tests, agents, stats; importing into an existing map preserves KMID). Versioning is Studio-driven: editable draft + immutable numbered versions, set-live per version, restore-to-draft; API selects versions via useDraft/version params on /start. Automated tests live in Studio, run against draft, exportable/importable as JSON. No webhooks anywhere in the docs (polling the interaction log is the documented alternative). However, Rainbird Labs ships an "Agentic Knowledge Engineering" Claude Skill (rainbird-graph-creation, pilot status, ZIP distributed via the login-gated Circle forum at forum.rainbird.ai) that "builds and uploads" knowledge graphs and runs live tests via the Reasoning Engine API, with "every graph update creates a new graph in your account" — implying a non-public graph-creation/upload API. Marketing (rainbird.ai/platform) additionally claims "Every knowledge graph published is available to your applications over the REST API and to your AI agents over MCP" / "Published as an MCP tool", plus a "RAKE (Rainbird Agentic Knowledge Engineer)" AI workbench — none of this has public developer docs yet.

SDKs. Official JS monorepo gitlab.com/rainbird-ai/sdk-js -> npm @rainbird/sdk (1.5.9, updated 2026-06-23; functions start/inject/query/response/undo/evidence/fullEvidence/interaction log + RESPONSE_TYPE_QUESTION/RESULT/UNKNOWN symbols; note it uses cf rather than certainty in inject/answer payloads), @rainbird/sdk-react (RainbirdProvider/InteractionProvider contexts, hooks, components), @rainbird/sdk-react-material (Material-UI, KitchenSink drop-in Q&A agent UI). Official Go SDK gitlab.com/rainbird-ai/sdk-go (v1.9.0, Aug 2024, MIT): Client{APIKey, EnvironmentURL} with EnvCommunity/EnvEnterprise consts (EnvEnterprise = "https://api-enterprise.rainbird.ai", which conflicts with the documented enterprise-api.rainbird.ai), NewSession(kmID, contextID, useDraft, version), ResumeSession, Session.Inject/Query/Response/Undo, Client.Evidence/Interactions/SessionFacts/KnowledgeMapVersion/Version, typed interaction events, error vars. Other GitLab repos: sdk-demo (Vite+React demo of sdk-react), rbdat (trivial gunzip-JSON pretty-printer). GitHub org is RainBirdAi (12 repos, nearly all archived: rainbird-standard-agent (old agent UI, archived 2021), rainbird-analysis-ui, chirpy-ui, reframe (triples->questions), triple-webservice, MSHack, docker-workshop, step-into-tech, owasp fork, liberal, corefoo-nlp, coding guidelines) — active development is on GitLab. Legacy npm wrappers: @rainbird/yolapi + @rainbirdai/yolapi (callback-style engine wrapper). No official Python SDK (PyPI rainbird/pyrainbird = Rain Bird irrigation, unrelated). Third-party: tom-sherman/coffeebird (DSL compiling to RBLang with a CLI, npm "coffeebird"), tom-sherman/rainbird-api-js, api-evangelist/rainbird-technologies (independent API profile with generated Postman collections for Decisions/Evidence/Platform).

DATA CONNECTORS (datasources): declared inside the KM, invoked lazily mid-inference (only when the engine needs the data, before falling back to asking a question; match->infer->ask order). RBLang: <datasource hostname path method(GET|POST) name> as a child of the string concept that is the request subject; {{%S}} = subject value; <input rel="..." subject="%VAR" object="%VAR"/> binds extra graph values (multi-hop paths supported) usable as {{%VAR}} in path/headers/body; <action map="relationship name=/Response/Path"/> maps response values to facts (XPath-style / separators, JSON path with / not .); <headers><header key value/></headers>; CDATA raw request bodies for POST/XML. Datasource-derived facts carry source:"datasource" and appear as datasource events in the interaction log with relationship+certainty.

TOOLING/SANDBOX: no official CLI or Postman workspace; docs explicitly recommend importing the OpenAPI spec (https://api.rainbird.ai/docs/openapi.yaml) into Postman. Public sandbox: HelloWorld demo KM with published API key 37582f71-b9b1-4451-b9e6-c130c7fd2412 and KMID 2fd1be28-b38d-4fa3-8b9d-b0976821912c on api.rainbird.ai (languages/speaks model). docs.rainbird.ai is GitBook: llms.txt index, every page fetchable as .md, and a ?ask=<question>&goal= natural-language query API on any page URL. Older docs at rainbird-ai.gitlab.io/rainbird-docs and rainbird.redoc.ly. Studio testing surface: Quick Query, NL test agent, automated tests, external UAT links; publishable web "agents" (shareable URL/iFrame, configurable back button, question grouping, evidence-tree link, certainty display, context identifier).

## Verified live 2026-10-07

Checked against the public HelloWorld sandbox on `https://api.rainbird.ai` (kmID `2fd1be28-b38d-4fa3-8b9d-b0976821912c`, the published key `37582f71-b9b1-4451-b9e6-c130c7fd2412`) using download, session and evidence calls only; no map was created. The map has the concepts person, language and country, the relationships `speaks` (plural, askable), `lives in` (singular, askable) and `national language`, and one rule: %S `speaks` %O, at most 75%, when %S `lives in` %COUNTRY and %COUNTRY has `national language` %O. The captured responses are the basis of the 0.0.14 test fixtures.

- **`knownAnswers` is filled from injected facts.** With `Tom lives in France` injected at certainty 90, querying `Tom speaks ?` produces the question "Where does Tom live?" with the injected fact in `knownAnswers`. One entry, with the relationship object shortened:

  ```json
  {"subject":"Tom","relationship":{"name":"lives in","subject":"person","object":"country","plural":false,"allowCertainty":true,"allowUnknown":false,"canAdd":"all","askable":"all"},"object":"France","cf":90}
  ```

  The certainty is `cf`, not `certainty`, and `relationship` is the whole relationship definition (it also carries `questions`, `metadata`, `fsid`, `allowCF`, `subjectDatasources`, `objectType` and `subjectType`), not just its name.
- **`question.canAdd` is a boolean on the wire** (`true` here). The relationship inside a `knownAnswers` entry carries Studio's string form instead (`"canAdd":"all"`).
- **A fact injected below 100% certainty is asked again.** Injected at 90, `lives in` (a singular relationship) is still asked, with the injected fact in `knownAnswers`. Injected at 100, it is not asked.
- **Skipping with known answers.** `unanswered: true` is accepted when `knownAnswers` is non-empty, even though the question's `allowUnknown` is false. Both body forms work: `{"subject":"Tom","relationship":"lives in","unanswered":true}` and the same with `"object":""`. The skip keeps the injected fact: the result was Tom speaks French at 71%, which is 75 × (0.5 × 0.90 + 0.5 × 1.00) = 71.25.
- **400 messages.** `unanswered: true` on a question with no `knownAnswers` and `allowUnknown` false returns 400 `{"err":["Please provide an expected boolean value for unanswered."]}`. Answering a relationship that was not asked returns 400 "Please provide an answer for an expected relationship."
- **Results** have the shape `{subject, relationshipType, object, certainty, factID, relationship, objectMetadata}`, alongside `queryProfile: []` and `sid`.
- **Evidence** needs no evidence key on the sandbox. Knowledge-map facts arrive with `source: "km"`, not `"knowledgemap"` as the OpenAPI enum says, so clients must accept both; the injected fact arrives as `"injection"` and the inferred one as `"rule"`. The rule node carries `rule.bindings` (`{"COUNTRY":"France","O":"French","S":"Tom"}`), `rule.conditions[]` in the order the rule declares them (one two-condition rule observed), each `{certainty, factID, factKey?, impact, object, objectType, relationship, salience, subject}` (`factKey` appeared only on the injected fact's condition), and `rule.ruleMaxCertainty` (75).
- **Impact.** impact = ruleMaxCertainty × salience/Σsalience × certainty/100. With weights 100 and 100, a cap of 75 and certainties 90 and 100, the two conditions report 33.75 and 37.5, which add up to the result's 71.25. The maximum possible impact of a condition, the grey part of Studio's salience chart, is therefore ruleMaxCertainty × salience/Σsalience (37.5 each here).
- **Downloading a map** (`GET /analysis/file/{kmID}`):
  - 200 returns only `{"rblang": …}`. There is no map name, so a downloaded draft is saved as `map-<first 8 characters of the ID>-draft.rbl`.
  - An unknown or malformed ID returns 404 `{"error":"File not found"}`, also with `?version=N`.
  - A version the map lacks returns 404 `{"error":"Can't find Version"}`.
  - A bogus key returns 401; no key returns 403 `{"error":"NO_PERMISSION"}`.
  - An upper-case kmID is accepted here and by `/start`.
  - Not checked: a valid key from another account.
- **Starting a session** with an unknown or malformed kmID (`GET /start/{kmID}`, draft or live) returns 400 with the plain-text body `Bad request!`, not 404.
- **A query needs a subject or an object.** A relationship alone returns 400 `{"err":["Please provide a string or numeric subject.","Please provide a string or numeric object."]}`. An object alone works.
- **Injecting facts.**
  - An unknown relationship returns 400 with a plain-text body such as `1) Could not find relationship for injection: Lives In.`.
  - A fact at certainty 0, or one that repeats a knowledge-map fact, returns 200 with a `warningLog` entry saying it was not saved.
- **An unknown or expired session** returns 404 `{"error":"Session ID not found"}` from `/response` and `/undo`.
- **Evidence for an unmet optional condition:** its factID is `WA:XX` (or `WA:XX:<hash>`), the fact is never stored, and its evidence GET returns 404 "Session ID not found".

From Rainbird's engine and app sources (not seen live): typed rule variables arrive as `{value, type}`, with dates in epoch ms; `alt` arrives with the bindings filled in, and an unknown variable shows as `[Unknown]`; a list-function key is the evaluated call, while `expression.text` is the rule text; min and max over an empty list return null; Rainbird's own apps (the stats UI, the unit tester, the natural-language chat) build `[STUDIO]/evidence?id=…&api=<full API URL>&sid=…`, and Studio reads `api` with URLSearchParams; an evidence key can only be POSTed (form field `key`), so a link cannot carry it.

Still open after this check: the plural case. The question and skip captures are all of the singular `lives in`, so for a plural question covered by injected facts it is assumed, not captured, that the facts appear in `knownAnswers`, that the engine accepts the automatic `unanswered: true` and that the injected facts are kept. The 0.0.14 default of `rainbird.query.autoSkipPluralQuestions` (`injected`) rests on the singular `lives in` check alone. Also still open: what `concepts` holds for truth, number and date questions; whether one `/response` may mix skipped and answered members of a question group; condition order in longer rules; and whether a link copied from Studio's own evidence share matches (the extension uses the format Rainbird's own apps build).

## Key facts

- [confirmed] Rainbird publishes an OpenAPI 3.1 spec (v1.2.0) at https://api.rainbird.ai/docs/openapi.yaml listing two servers: https://api.rainbird.ai (Community) and https://enterprise-api.rainbird.ai (Enterprise) — https://api.rainbird.ai/docs/openapi.yaml
- [confirmed] Session lifecycle: GET /start/{kmID} (X-API-Key; optional useDraft/version params) returns {id, kmVersion.id}; then POST /{sessionID}/inject, /{sessionID}/query, /{sessionID}/response, /{sessionID}/undo; query/response/undo each return either a questionResponse or a resultResponse — https://api.rainbird.ai/docs/openapi.yaml
- [confirmed] Query body is {subject?, relationship (required), object?} — supply subject, object, or both to ask Tom->speaks->?, ?->speaks->French, or Tom->speaks->French — https://docs.rainbird.ai/rainbird/developer-docs/api-guide/example-api-requests.md
- [confirmed] Question objects carry dataType (string|number|truth|date), type (First Form yes/no vs Second Form Subject/Object), plural, allowCF, allowUnknown, canAdd, prompt, knownAnswers, concepts[] (candidate answers), and grouped questions arrive in extraQuestions[] — https://api.rainbird.ai/docs/openapi.yaml and https://docs.rainbird.ai/rainbird/knowledge-modelling/modelling-features/relationships/question-configuration.md
- [confirmed] Answers are posted as {answers:[{subject,relationship,object,certainty?,answer:'yes'|'no' for first-form}]}; skipping uses "unanswered": true, accepted when the question has allowUnknown or non-empty knownAnswers and a 400 otherwise (the docs page mentions only allowUnknown; the knownAnswers case was verified live 2026-10-07); undo rolls back the last answer array and re-returns the question — https://docs.rainbird.ai/rainbird/developer-docs/api-guide/skipping-an-answer-to-a-question.md and openapi.yaml
- [confirmed] Results carry certainty (1-100) and a factID per result; GET /analysis/evidence/{factID}/{sessionID} returns fact source (knowledgemap|rule|answer|injection|datasource|synthesis; knowledge-map facts arrive as "km" live), rule bindings, and conditions with impact/salience/certainty/wasMet; the full evidence tree is retrieved by recursively following condition factIDs — https://api.rainbird.ai/docs/openapi.yaml and https://docs.rainbird.ai/rainbird/developer-docs/api-guide/retrieving-a-full-evidence-tree-for-use-with-a-custom-ui-or-application.md
- [confirmed] Auth = X-API-Key header (key on Account page / KM Publish page); legacy HTTP BasicAuth still supported; evidence and interaction-log endpoints need separate x-evidence-key / x-interaction-key headers unless link-sharing is toggled on in Studio — https://api.rainbird.ai/docs/openapi.yaml and https://docs.rainbird.ai/rainbird/knowledge-modelling/publishing-your-km/api-management.md
- [confirmed] inject/query/response/undo require no API key in the spec (security:{}) — the sessionID from /start is the effective credential — https://api.rainbird.ai/docs/openapi.yaml
- [confirmed] GET /analysis/interactions/{sessionID}?format=json|csv returns start/inject/query/question/answer/result/datasource events; recording is off by default and enabled per KM version ('Record Interactions') in Studio — https://api.rainbird.ai/docs/openapi.yaml and https://docs.rainbird.ai/rainbird/knowledge-modelling/publishing-your-km/setting-a-live-version.md
- [confirmed] GET /analysis/session/{sessionID}?filter=version|facts returns KM version metadata or all session facts partitioned global/local/context with per-fact source — https://api.rainbird.ai/docs/openapi.yaml
- [confirmed] Beta NL endpoints: POST /nl/interact (X-API-Key + required 'Version: v1' header; {sessionID,userPrompt} -> responseType question|result|error, extracted query, injected/invalid/unmatched facts, llmTokens metadata; one active query per session) and POST /nl/explain ({language,sessionID,factID,instructions?} -> natural-language explanation); both use Anthropic models on AWS Bedrock, EU-processed — https://api.rainbird.ai/docs/openapi.yaml and https://docs.rainbird.ai/rainbird/developer-docs/api-guide/beta-apis/interact.md
