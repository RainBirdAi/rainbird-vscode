# Changelog

## 0.0.14 — 2026-10-08

- **Open your Studio maps by Knowledge Map ID.** New command **Rainbird: Open Map by Knowledge Map ID…** brings one of your Studio maps into VS Code. Run it from the Command Palette, the Maps view's title bar, the sidebar's welcome text or the walkthrough's new **Open your own map** step, and paste the map's Knowledge Map ID. It connects first if no API key is stored, downloads the map's draft RBLang, saves it as a `.rbl` where you choose (your folder by default, as `map-<first 8 characters of the ID>-draft.rbl`), opens it and binds the file to the map, so the play button, the diffs and the assistant use that map without asking. The map is also listed in the Maps view. A wrong ID, a rejected key and a key without access to the map each get a message that says what to check. Saving a draft into a file also records a snapshot, so the gutter change bars and **Rainbird: Diff Against Last Pulled or Pushed Snapshot** (renamed from "Diff Against Last Pushed Snapshot") show what you have changed since. When the Maps view is empty, it explains that the Rainbird API cannot list your Studio maps and offers to open one by Knowledge Map ID. The getting started guide, the README and the walkthrough now start from bringing your own map in: open it by Knowledge Map ID, extract a `.rbird` export, or paste from Studio's `</>` code panel. They also say that the walkthrough's example map can be explored offline but must be pushed before it can be queried.
- **One Knowledge Map ID prompt, one map order.** A new Knowledge Map ID prompt shows an example and where to find the ID (the map's Publish page, or **View Knowledge Map ID** in the map details menu), lists the maps in the Maps view, offers an ID it finds on the clipboard, takes a pasted ID or Studio link and warns about text that does not look like an ID. Opening a map, binding a file, **Add Map by kmID…**, Pull, **Diff Open File Against Platform Draft**, **Compare Draft vs Saved Version…**, **Ask in Natural Language**, the query panel and **Run Query (Quick Pick)…** all use it. Pull, the two platform diffs, **Ask in Natural Language**, the query panel and **Run Query (Quick Pick)…** also pick the map in the same order: the file's own binding, then `rainbird.knowledgeMapId`, then the prompt, whose answer becomes the folder's default (before, the Quick Pick runner read `rainbird.knowledgeMapId` first, so for a bound file it may now query a different map). The query panel now queries, records and saves tests against the map named in its header; before, it could show one map and query the one in the setting. The query panel's header has **Change…** (**Choose map…** until a map is chosen), which binds the panel's file to another Knowledge Map ID, or asks for an ID when the panel has no file. A Knowledge Map ID that is wrong, or that belongs to another environment, now gets "No map with Knowledge Map ID … is visible to this API key on …" in the query panel, the Quick Pick runner, the assistant's `run_query` tool and test replay, instead of a raw "Rainbird API 400 … Bad request!"; the panel also shows it on the setup card when the platform has no such map. The query panel and `run_query` add a map to the Maps view only once a query against it has started. New command **Rainbird: Bind Open File to a Knowledge Map ID…**, also on the editor's right-click menu, points a file at a map; **Extract RBLang** offers it when it finishes, since a `.rbird` export does not carry the ID. **Rainbird: Pull Map RBLang from Platform (read-only draft or saved version)…** is retitled to say what it is for, and its **Save as .rbl…** now binds the file too. The extension now starts with VS Code, so RBLang pasted into a new file is recognised in any window.
- **Searchable goal picker.** The query panel's goal field is now a search box. Type part of a relationship's name, its subject or its object, then pick from the filtered list with the arrow keys and Enter, or with the mouse; with nothing typed, the relationships that rules infer are listed first. Each row shows what the relationship links, whether it is plural, how many rules infer it and how many facts the map holds for it. Relationships with no rules or facts are marked, and an `askable="none"` one with no rules or facts warns that the engine cannot answer it without injected facts. A name that matches nothing can still be sent as typed. When your spelling differs from the map's only in case, a hint says so and **Start query** uses the map's spelling. Pressing ▶ with the cursor in a relationship's declaration, a rule or a fact preselects its relationship (anywhere in a rule, conditions included, the relationship the rule infers; ▶ asks first if a query is in progress), and the last goal you ran against each map is remembered. Enter in the goal, subject or object field starts the query once the goal is one of the map's relationships; to send another name, click **Start query** (a name that partly matches one asks first, and a second click sends it as typed). The setup card now says to fill the subject (to ask "what does Fred …"), the object ("who …") or both (how certain one fact is), instead of suggesting both could be left empty, which the engine rejects. **Start query** with both empty says "Fill the subject, the object or both…" and sends nothing, and the assistant's `run_query` tool refuses a query with neither. When a query cannot start (the engine rejects the injected facts, the goal or Knowledge Map ID is unknown, or there is no live version or no such version), the setup card comes back with everything you entered and the reason under it. **Rainbird: Run Query (Quick Pick)…** also matches its goal list on subject → object and on the rule and fact counts, lists the relationship at the cursor first, asks for an object when you leave the subject empty, and shows date results as `YYYY-MM-DD`. The walkthrough's query step now opens the query panel the docs describe, rather than the Quick Pick runner.
- **Answer controls that match the question.** Question cards are now built from the type of answer the engine wants, not from the suggestions it sends. Truth questions always show **True** and **False**. Number questions show a number field with the hint "A number, e.g. 42 or 3.5", and a value that is not a plain number is caught before anything is sent. Date questions accept dates written the usual ways (`1st October 1981`, `1 Oct 1981`, `October 1, 1981`, `1981-10-01`) or picked from a calendar, show what will be sent ("Will send 1981-10-01 (Thursday 1 October 1981)") and send `YYYY-MM-DD`, the format the engine accepts. A date that could be read either way, such as `01/10/1981`, is never guessed: the card offers both readings and cannot be sent until you pick one (new setting `rainbird.query.dateOrder`, `day-first` or `month-first`, decides which reading is listed first). Number and date questions always have a field, even when the map suggests values; the suggestions fill it. Options are de-duplicated, dates among them show as `YYYY-MM-DD` instead of timestamps, long lists get a filter box, and **Or something else** appears only when the map lets new values be added. When the engine rejects an answer, the card says what it expects and keeps what you entered. The certainty slider no longer goes below 1, the lowest certainty the engine accepts. The Quick Pick runner and the assistant's `run_query` tool follow the same rules; as they cannot offer a choice, they reject an ambiguous date and suggest an unambiguous form such as `1981-10-01` or `1 October 1981`. New setting `rainbird.query.logQuestions` writes the raw JSON of every question the query panel receives, and each answer it sends, to the **Rainbird** output channel.
- **Grouped questions fill in like a form.** When the map groups questions (the `group` attribute on relationships), the card now works like a form. Choose or type every answer — Yes/No, True/False and options toggle, several chips can be ticked, and **Don't know** or **No more** toggles too — then click **Submit answers** once. Before, each answer needed its own Submit before the group's button woke up. Enter in a text field moves to the next unanswered question, or submits when none is left. Questions still missing an answer are highlighted with a short message, the footer counts them, and focus moves to the first. If the engine rejects one of the answers, the card comes back with all your answers kept and a note asking you to fix the one in question. If Rainbird does not reply to an answer or to an automatic **No more**, the card comes back with your answers kept and a note, so you can send it again; if **Back** gets no reply, an error explains why and the card or result you were on comes back. ▶ asks before replacing a query only while its session is still alive. A single question keeps its one-click answers, and each new card takes the keyboard focus (its field, or its first button); a result card focuses **Show evidence**. The Quick Pick runner no longer answers only the first question of a group.
- **Known answers and No more on plural questions.** Question cards now show what the engine already knows for the question, for example "Already known: English (injected), French", from the engine's `knownAnswers`, marking the values that came from facts you injected. A plural question with known answers offers **No more**, which tells the engine there is nothing to add, and shows the known values as ticked chips that are not sent again. A single-answer question with a known answer offers **Keep known answer**, and **Don't know** stays where the map allows it. By default the panel answers **No more** for you when the facts you injected already cover a plural question (for a card with several questions, when they cover every one; otherwise the covered ones start on **No more**). The transcript says "\<question> — answered “No more” automatically: already known from injected facts: …" ("already known: …" with the `known` setting), with an **Answer instead** link, which brings the question back while the skip is still the last step. New setting `rainbird.query.autoSkipPluralQuestions`: `injected` (the default), `known` (skip whenever the engine already has answers, whatever their source) or `off`. Saved tests record a skip as an ordinary answer and replay it whatever the setting is. Test replay now also checks the subject (the object, for a subject question) of each recorded answer, so a test whose recorded answer names a different instance reports an unrecorded question instead of sending it; a recorded skip the engine now refuses is explained. If the engine refuses a skip, the card says so, asks the question and suggests `askable="none"` for a relationship that only ever comes from injected facts, as long as every session injects them. When the panel's `.rbl` or another open `.rbl` declares the relationship, **Make “\<relationship>” inject-only…** sets it there after a confirmation; the change is not saved, and pushing creates a new map. Injected facts whose subject or object differs from the question's only in case are flagged on the card. The assistant's `run_query` tool skips covered plural questions the same way and reports what it skipped, and the Quick Pick runner offers **No more** too. Checked on Rainbird's public HelloWorld map with the single-answer relationship `lives in`: injected facts appear in `knownAnswers`, a skip keeps them, and a fact injected below 100% certainty is asked again, with the injected value shown as already known.
- **Evidence tree laid out like Studio's.** The result is a card with a coloured source badge (rule, answer, injected, datasource, knowledge map), its certainty and its subject, relationship and object, and a legend explains the colours. A rule lists its conditions in the order the engine reports them, one row each: the fact that satisfied the condition, with its own source badge and certainty, and an impact bar on a 0–100 scale whose grey part shows the most that condition could contribute. When another rule inferred that fact, that rule's card is nested under the row, collapsed. List functions such as `sumObjects(…)` show the call, the result and each fact they used, so the inputs behind a total are no longer missing. Optional conditions that were not met are struck through and keep their 0%, zero-weight conditions are listed separately, and an expression condition shows its text with ✓ or ✗ instead of printing a variable name as if it were the result. **Inputs used by this result** lists every answer, injected fact, datasource fact and map fact behind the result. The toolbar has **Expand all**, **Collapse all**, **Open in Studio**, **Copy link** and **Open in panel**, which opens the same tree in its own tab. Studio links follow Rainbird's documented evidence link format and open only while the query session exists; the Studio address is worked out from `rainbird.apiUrl` for Rainbird-hosted environments, and the new `rainbird.studioUrl` setting covers other hosts. A locked tree now says how to unlock it — turn on **Evidence Tree Link** in Studio, or enter the map's evidence key — with **Retry**, for after you turn on Evidence Tree Link, and **Set evidence key…**, which loads the tree again once the key has changed. **Show evidence** now toggles with **Hide evidence** and keeps a loaded tree. A tree with facts that could not be loaded offers **Retry**, an expired session says to start a new query, a failed **Explain (AI)** can be tried again, and date results show as `YYYY-MM-DD`. **Rainbird: Show Evidence Tree for Fact…** uses the same view, and the graph overlay, the promotion diff, the assistant's `get_evidence` tool and the panel's **Explain (AI)** read the same tree, list-function inputs included. **Explain (AI)** gives the model the panel's own map file, or none for a map chosen by Knowledge Map ID; before, it sent the first `.rbl` visible in an editor, which could be a different map.
- **Reload from Studio, a readable graph, neutral answer buttons.** New command **Rainbird: Reload Map from Studio** (also in the editor's right-click menu, and as a **Reload from Studio** button on each map in the Maps view) replaces a bound file with what its map's draft holds now, so edits made in Studio come back into VS Code; if the file has changes since its last pull or push you are warned first and offered the differences, the replacement is one undoable edit, and the draft becomes the new snapshot for the gutter bars. A read-only platform tab simply refreshes. The graph view no longer draws several relationships between the same two concepts on top of each other: they fan out as separate curves, a relationship running the other way gets its own curve, a concept's relationships to itself are drawn as separate loops, every relationship has an arrowhead, and labels keep clear of each other and of the lines. Yes and True are no longer highlighted on question cards, and a card answered with buttons focuses the question rather than its first button, so nothing looks like a recommended answer. New command **Rainbird: Get Started** opens the walkthrough directly.
- **Under the hood.** The query panel's webview moved out of `src/queryPanel.ts` into `src/queryPanelHtml.ts`, assembled from regions under `src/queryWebview/` (base, setup, questions and results), each owning its CSS and script. New VS Code-free modules, each with a `node:test` suite: `answers.ts` (answer controls, value formatting, coercion and date parsing), `questionSkip.ts` (known answers, skip labels and the auto-skip rules), `goalFilter.ts` (goal search and ranking, also run inside the webview), `goals.ts` (the goal list with plural, askable and rule and fact counts, for the open file and the platform draft), `kmId.ts` (finding a Knowledge Map ID in pasted text, default file names), `evidenceModel.ts` (one nested evidence model with a fetch budget), `evidenceRender.ts` (the Studio-style renderer shared by the panel and the evidence tab) and `studioLinks.ts` (Studio addresses and evidence links). Webview behaviour is tested by loading the panel into happy-dom. `npm test` grows from 224 to 603 tests.

## 0.0.13 — 2026-09-29

- **AI assistant rebuilt as a Co-author for the editor.** The sidebar assistant now works on the open map through tools instead of pasting whole maps into the chat: it reads a structured overview of the map (concepts, relationships, facts, rules, diagnostics), reads line ranges or named elements, and edits the file with validated element-level operations — insert an element into the right section with the file's indentation, replace or delete an element, set an attribute, or replace exact text — applied atomically, re-linted, and reported back with the diagnostics delta and the model-level changes. By default edits land in the editor as the assistant works, each one undoable, and every turn that changed the file opens a before ↔ after diff automatically (`rainbird.ai.showDiffAfterEdits`, on by default) and gets a **Changes** card with **Show diff** and **Undo this turn**; the new `rainbird.ai.applyEdits: "preview"` setting collects edits into a proposal shown as a side-by-side diff with **Accept** / **Reject** instead. It can also start a new map from a description, lint fragments in the context of the open map (so a proposed rule no longer shows bogus "missing root" errors), run live queries that continue a session across calls, push the open map (still confirm-gated), fetch evidence trees, replay `.rbtest.json` regression tests and compare the map with git HEAD or the last pushed snapshot.
- **It knows RBLang.** The system prompt carries a bundled reference (about 17k tokens, cached for an hour) covering the platform, document structure, concepts, relationships and question forms, instances, facts and typed literals, rules, conditions, variables, the expression language and its left-to-right evaluation, datasources, linked maps, the certainty model with a worked example, Match → Infer → Ask, naming rules and engine limits, the linter's findings in plain words, the official 20-point validation checklist, authoring patterns, common mistakes and six worked example maps that the unit tests lint. The element and function tables are generated from the same schema the linter uses.
- **Better conversations.** Each turn carries a compact context header (file, size, cursor and selection, diagnostic counts, connection and kmID, whether the file changed since the previous turn); small maps are inlined once and re-sent only when they change, larger maps are read on demand, and nothing is truncated silently. Requests use adaptive thinking with a configurable effort level (`rainbird.ai.effort`), prompt caching, eager tool-input streaming and server-side clearing of old tool results; the tool-round cap (now 25) ends with a summary instead of silence; API errors are explained (invalid key offers to set one). The chat renders markdown, shows tool activity as collapsible steps, streams the model's reasoning summary while it thinks, and reports token usage and cache hits. `rainbird.ai.model` is now a dropdown. **Explain with AI** works even when the sidebar was never opened, and the query panel's evidence explanation uses a dedicated narrator prompt.
- **Under the hood.** The agent loop (`src/agentLoop.ts`), tool schemas and validation, map overview, context header, edit engine (`src/mapEdits.ts`) and knowledge reference are VS Code-free modules with `node:test` suites; `npm test` grows from 179 to 223 tests. The semantic-diff model moved to `src/semanticModel.ts`.

## 0.0.12 — 2026-09-29

- **Rename as you type.** Editing a concept, relationship or instance name where it is declared now updates every mention live — `rel` subjects and objects, `concinst` types, `relinst` types, `condition` and datasource `input` `rel`s, `action map=` targets, quoted names in expressions and `{{%VAR.relationship}}` traversals — using VS Code's linked editing, which the extension turns on for `.rbl` files (`"[rblang]": { "editor.linkedEditing": false }` turns it off). Only the declaration triggers it: typing in a reference still just edits that reference, since that is usually meant to point it at a different symbol. `F2` rename is unchanged and works from any mention. Instance renames, live or `F2`, are now scoped to the instance's concept: renaming `France` the Team leaves `France` the Country and its facts alone. Hovering a name shows what it is, how much of the map uses it, and the rename shortcuts. Symbol resolution moved to `src/symbols.ts`, free of the VS Code API, and `npm test` gains a *symbols* suite.

- **Linter: unused relationships.** A `<rel>` that no fact, rule, condition or datasource refers to is now reported as a hint, `Relationship "x" is declared but never used`, with a **Remove this declaration** quick fix — the relationship-level twin of the existing unused-concept hint. A reference is anything rename already follows: a `relinst` type, a `condition` or datasource `input` `rel`, a datasource `action map=` target, a quoted name inside an expression and a `{{%VAR.relationship}}` traversal in evidence text. Maps with `<import>`s are not checked, since a linked map may use the relationship, and a relationship the reachability check already reports is not reported twice. `examples/broken/diagnostics-tour.rbl` and `npm test` cover the new check.

## 0.0.11 — 2026-09-18

- **Formatter.** RBLang now has a document and selection formatter, so **Format Document**, **Format Selection** and `editor.formatOnSave` work on `.rbl` files (and on `.xml` files recognised as RBLang). Each line is re-indented from the element nesting and trailing whitespace is trimmed. Nothing else changes: line breaks, blank lines, comments, wrapped attributes and element order stay as written, and lines that continue a wrapped tag or multi-line comment shift with their first line so hand-aligned attributes stay aligned. Lines inside a quoted attribute value or CDATA section are left alone. Half-typed documents are handled: a stray closing tag is ignored and a mismatched one closes back to its opener. RBLang files default to a two-space indent; the editor's own indentation detection still applies to files that use tabs. `npm test` gains a *formatter* suite that includes an idempotence check over the example maps.
- **GitHub repository moved to the RainBirdAi organisation.** The repository, issues and homepage URLs in `package.json` and the README now point at `github.com/RainBirdAi/rainbird-vscode` instead of the previous personal account. The README also shows the GitLab pipeline status badge.

## 0.0.9 — 2026-09-14

- **Released under the MIT licence.** The previous LICENSE only covered internal evaluation by selected testers, which did not match Marketplace distribution. The extension is now open source under MIT, copyright Rainbird Technologies Ltd, and `package.json` declares the `MIT` SPDX identifier.
- **RBLang in `.xml` files is recognised.** Maps saved with the `.xml` extension the platform and Studio hand out now get the full language support — linting, Map Explorer, graph view, push, diffs, guided authoring — without renaming. When an XML (or plain-text, or untitled) document opens, the extension looks in its first 2 KB for `xmlns:rbl="http://rbl.io/schema/RBLang"` or a bare `<rbl:kb>` root and switches the document's language to RBLang. Only documents VS Code typed by default are switched; one the user set to another language by hand is left alone, as is every other XML file. RBLang pasted into a new untitled document is recognised as it is typed. The extension now also activates when an XML file is opened. `npm test` gains a *detection* suite.
- **`.rbird` exports show the Rainbird mark as their file icon**, like `.rbl` files, in file icon themes that support language icons (such as the default Seti theme). The export is gzip-compressed JSON, so opening it still shows VS Code's binary-file notice; use **Extract RBLang** or **Compare Draft vs Saved Version** from the right-click menu as before.

## 0.0.8 — 2026-09-11

- **Linter: the bare `&` check from 0.0.7 has been removed.** A `&` that does not start an entity is no longer reported in attribute values or text, and the **Replace with &amp;** quick fix is gone with it. ## 0.0.7 — 2026-09-11

- **Linter: document-structure checks aligned with the platform parser's acceptance tests.** Two gaps closed: a document with no `<rbl:kb>` root (plain text, or just the `<?xml …?>` declaration) is now an error at its first line, as is a second root; a bare `&` that does not start an entity is an error wherever it appears — attribute values and text, with a **Replace with &amp;** quick fix — except in a datasource `path`, where the importer tolerates raw query strings. `npm test` gains a *document structure* suite that runs the parser's cases end to end: missing or mismatched root tags, wrong prefix or local name, stray text inside `rbl:kb`, `concept`, `concinst`, `rel`, `relinst` and `condition`, unclosed and mismatched child elements, LLM-style preface/postscript/code fences (errors in a file), and the optional XML declaration. Two false positives removed, confirmed against a map the platform accepts: apostrophes are allowed in names (`Retired's`), so the name-character rule now forbids only `" \ < >` in the linter, rename and the guided flows; and expression string literals may escape an apostrophe as `\'` (`'Retired\'s'`), which the quote-balance check, the left-to-right analyser and quoted-name references now understand. The warning that a custom variable appearing only once in a rule binds nothing has been removed: a variable bound in one condition and read only by the engine's output is legitimate.

## 0.0.5 — 2026-09-10

- **Guided authoring — edit RBLang without knowing RBLang.** `＋ Insert…` (editor title bar, right-click menu, Map Explorer title) and a `＋` on each Map Explorer category open short guided flows for a concept, relationship, instance, fact, rule or condition. Every choice is a pick from what the map already declares (string concepts for subjects, instances of the right concept for facts, `%S` / `%O` / already-bound variables for conditions), with a “New …” escape hatch that declares the missing piece first. The element is inserted in the docs' recommended section of the file with the file's own indentation, and the cursor lands on it. Rules are built condition by condition with a running `IF … AND … THEN …` summary. CodeLenses add `＋ fact` and `＋ rule` to every relationship and `＋ condition` to every rule. The Map Explorer gained a collapsed **Facts** category.
- **Diffs are now side by side.** `Rainbird: Diff vs git HEAD…` (was “Semantic Diff”), `Rainbird: Compare Draft vs Saved Version…` and `Rainbird: Diff Open File Against Platform Draft` open both RBLang sources in VS Code's diff editor — added, removed and changed lines highlighted like `git diff` — instead of a markdown file. The model-level semantic report is unchanged: the notification counts the changes and a **Semantic report** button opens it. Git HEAD, Studio `.rbird` exports and platform versions all appear as read-only documents on the left side.
- **Linter: parity with Studio's validator, minus linked maps.** Studio's RBLang linter was compared check by check with the extension's; everything it caught that we did not is now covered, and the checks where we were stricter than Studio and the engine were loosened. False positives removed: an instance is identified by **name + concept**, so the same name under two concepts is no longer a duplicate and no longer trips the subject/object type check; `type="boolean"` is accepted as a legacy spelling of `truth` (hint + rename fix instead of an error); typed literals in facts and conditions are checked against the **platform's** rules, which are stricter than Studio's linter — dates must be ISO-8601 (`YYYY-MM-DD`, optional time) or epoch milliseconds, truth values exactly `true`/`false`, numbers within 15 digits — and reported in the platform's own words (“Relationship *x* expects a date as its object”), so the lint error reads like the push error it prevents. New checks: empty attribute values (`name=""`) are errors, as in Studio's “Please specify…”; a lexical layer reports malformed attributes, duplicate attributes (first value wins, with a remove fix), unbalanced double quotes at the tag they break, text outside elements, elements never closed and closing tags with nothing open — cases the regex tokeniser used to misparse silently; datasource `<input>`s must name a known relationship and may only bind `%S` where that relationship expects the datasource's concept. Duplicate concepts and relationships are now **errors** (Studio rejects them); duplicate instances and facts stay warnings. Not done: resolving `<import>`ed maps — references to symbols defined in a linked map still show as unknown.
- **Unit tests for the linter.** `npm test` runs a `node:test` suite over the linter core (`src/test/lint.test.ts`) with no VS Code host: one small RBLang snippet per behaviour, every quick fix applied and re-linted to prove it clears its finding, the maps in `examples/` as an error-free regression corpus, and `examples/broken/diagnostics-tour.rbl` — a deliberately broken map with an `EXPECT` comment above every bad element — checked block by block so that each documented finding still fires and nothing unexplained appears. Open that file in the Extension Development Host to eyeball every diagnostic and quick fix at once. The editor-agnostic core moved to `src/lint.ts`; `diagnostics.ts` is now only the VS Code adapter (same exports).
- **Fix**: the ＋ buttons on the Map Explorer's category headers (Concepts, Relationships, …) opened a brand-new untitled document and inserted the element there instead of into the map being shown. VS Code hands an inline tree command the tree item itself; the authoring flows took any truthy argument for a file Uri and passed it to `openTextDocument`, whose options overload creates a new file. Category items now carry the Uri of the document the tree shows, the commands read it from there, and a non-Uri argument falls back to the active `.rbl` editor.
- **Platform validation errors are shown where they belong.** Verified live: `POST /maps` does not reject an invalid map — it answers **201 with a kmID**, stores the draft as-is, and puts the first problem it found in an `error` field (“Line: 35 - Datasource hostname must start with …”). The extension read only the kmID and reported a clean push. It now reads that field (and the `err` list of a genuine rejection): the push notification becomes a warning quoting the message, and the platform's messages are placed on the elements they are about — for a literal the platform would reject, every fact or condition carrying such a literal; otherwise the relationship, concept or instance named, a `Line: N` position when the message has one, else the root element — and published in the Problems panel under the source **Rainbird platform**, next to the local lint. The full list also goes to the new **Rainbird** output channel (“Show all”). They stay until the next push of that file or until it is closed. The assistant's `push_map` tool reports the same list back to the model, and marks the open document too when it pushed that document's text.

## 0.0.3 — 2026-09-03

- **Query panel**: grouped questions (`extraQuestions`) are now shown together and answered in one call — previously only the first question of a group was answered and the session desynchronised. Added **↶ Back** (`POST /undo`), a **facts-to-inject** box (JSON or CSV, or load a fixture file), a **draft / live / version** target picker, and an optional **object** so subject queries and first-form certainty queries work. When a map has no live version the engine silently serves the draft; the panel and the promotion diff now say so. Saved tests record the target and injected facts and replay them.
- **Promotion diff** (`Rainbird: Compare Versions…`, also “Compare with another version…” on a result): replays a saved test or the last panel session against two versions of the same map (draft vs live by default) and reports result and certainty changes plus, when evidence is accessible, the facts, rule conditions and impacts that moved.
- **Platform as a source of RBLang.** `GET /analysis/file/{kmID}[?version=N]` (verified live; not in the public spec) returns a map's RBLang for the draft or any saved version. Built on it: **`Rainbird: Compare Draft vs Saved Version…`** (platform draft vs latest / live / numbered version, or against a Studio `.rbird` export or the open `.rbl`, with a semantic report and an optional side-by-side text diff; also on right-click of a `.rbird`); **`Rainbird: Pull Map RBLang from Platform…`** (read-only view of the draft or a version, with Save As); **`Rainbird: Diff Open File Against Platform Draft`** (the honest “am I in sync?” check); the **Maps view** now opens the real platform draft instead of a push snapshot; the **query panel** lists goals from the platform draft when no `.rbl` is open. The plain semantic diff’s base picker accepts `.rbird` exports too.
- **Semantic diff** now pairs rules that were renamed or newly named (instead of reporting a removal plus an addition) and describes condition weight / mandatory changes on the same condition instead of listing it twice.
- **Quick diff against the pushed snapshot**: gutter change bars and `Rainbird: Diff Against Last Pushed Snapshot` compare the local buffer with exactly what was last pushed from VSCode.
- **Rename now cascades** into quoted relationship/instance names inside expressions (list functions), `{{%VAR.relationship}}` traversals in evidence text and datasource `action map=` targets — Studio has propagated renames into expressions since 4.88, and a rename that missed them silently broke the map.
- **New diagnostics**: left-to-right evaluation warning with two quick fixes (keep the engine’s order / use conventional precedence) and an inlay hint showing how the engine reads the expression; reachability (“can only be satisfied by injected facts” on relationships, “this rule can never fire” on rules) in conversational maps; recursive-rule hints with the cycle path.
- **AI assistant** `run_query` tool handles grouped questions and accepts `object` and `version`.
